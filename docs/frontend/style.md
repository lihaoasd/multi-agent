# 前端风格与页面设计 · Agent Haness

> 类别：frontend · 状态：草稿(待评审) · 决策依据：D10（React+Vite）、prd FR-12、US-1/5/8/12
> 关联：[architecture.md](../design/architecture.md)、[api/contract.md](../api/contract.md)、[meetings.md](../design/meetings.md)

## 1. 技术基线

- React 18 + Vite + TypeScript；UI 组件库 **Ant Design 5**；状态：轻量（zustand 或 context）按页面/会话域拆分；实时走 WS（见 api/contract.md）。
- 主题：默认浅色 + 可切换深色；主色建议品牌蓝（#2F54EB 系），状态色遵守 AntD 语义（成功绿/警告橙/错误红）。
- 语言：界面中文；无 i18n 需求（预留 token）。

## 2. 页面结构

```
/                    项目列表页
/projects/new        创建项目向导
/projects/:pid       三栏工作台（核心）
  ├ 左栏  团队成员与状态
  ├ 中栏  会话窗口（聊天流/会议视图/审批卡片）
  └ 右栏  Tab：会话列表 | 产出物 | 任务 | 记忆 | 项目信息
/settings/roles      系统角色库管理（模板 CRUD/预览；内置只读，变更=「基于内置复制新建」，D16-⑤/B12）
/settings/models     模型 Provider 配置（或并入 config 页）
```

### 2.1 项目列表页

- 卡片/表格列出项目：名称、工作目录路径、成员数、最近活动、创建时间；操作：打开/重设工作目录/删除(二次确认，说明仅删平台数据)。
- "新建项目"按钮 → 向导。

### 2.2 创建项目向导（US-1）

步骤：
1. 名称 + 描述（可选模板化：空项目 / 已有仓库）；
2. **选择工作目录**：文本输入 + "浏览"（调用后端目录浏览器 `/api/fs/browse`——用户级全盘浏览，见 api 文档；支持空目录或已有仓库嗅探提示 git/package.json 等）；
3. 勾选团队：从角色库多选（**默认全勾 8 个内置模板**，D14-1，可取消）；可展开逐个配置 displayName、提示词、模型、loop；
4. 确认创建 → 进入三栏工作台，自动生成每位角色的 user 会话。

### 2.3 三栏工作台（核心，prd §5 页面描述）

布局：CSS Grid 三列，宽度可拖拽调节（左 260 / 中 flex / 右 300 默认），窄屏（<1100px）右栏变抽屉；顶部项目条（返回/项目名/全局搜索/**「需你处理」待办条**/**进行中细条**）。

**「需你处理」待办条（顶部常驻，D17-③）**
- MVP 仅聚合**阻塞级三类**，按优先级排：会议拍板（blocked，全体冻结）＞ 高危命令审批（该 Agent 阻塞）＞ 成员入会干预（强制接受/拒绝/召离）。
- 每条显示来源（哪个会议/Agent/命令摘要），支持**原地操作**（拍板/批准/强制决定），处理完即消失；点击跳转源会话。doc 提交审批与任务完成确认**不**进本条（低打扰，留在各自原位）。全量聚合（含跨项目）P1。

**进行中细条（顶部，MVP 最薄版，D17-⑥）**
- 常驻一条「n 个 Agent 正在工作 · 点击查看」，点击弹出列表：Agent × 任务 × 进行到第几步（plan 事件驱动），可跳转对应会话；无进行中工作时不显示。完整活动面板（步骤进度可视化）P1。

**左栏 团队与状态**
- 成员列表：头像(模板图标)+名称+状态徽标（`空闲/工作中/会议中/等待中/停用`，蓝/绿/橙/灰/灰描边）+所在会话提示（hover 显示）。
- 点击成员 → 中栏切到该成员的 **user 会话**（长期会话）；已停用成员会话只读（历史可查，不可发送，D14-9）。
- 成员操作菜单：改名/换模型/换 loop/调提示词（同创建向导）、**停用/启用**（停用保留全部数据，可随时启用继续原会话）。
- **停用反馈（D17-⑦，B6 配套）**：对 working/meeting 实例点停用 → 进入"待停用"：条目灰化+「待停用」角标，提示"当前回合/会议结束后生效"，期间可**取消停用**；对 waiting（审批等待）实例点停用 → 弹窗列出其未处理审批并给"去处理"入口。
- **主持人征询标签（D17-⑦）**：Agent 处于 proposed 征询期（主持人身份）时，其条目显示「主持征询中」弱标签，hover 显示邀请进度（已接受/稍后/拒绝），点击跳到对应会议会话。
- "＋会议"按钮（P1，U5 之前仅 Agent 可发起，此处只展示进行中的会议条目与排队中的发起）。

**中栏 会话窗口（核心交互）**
- 会话头部：会话名 + 参与者（user 会话：成员卡片；meeting：主持人/成员徽标+议程进度）+ **视图切换：对话 / 原始时间线**（D14-④：时间线按 kind 过滤展示全部事件——thought/工具/审批/产物/状态/摘要/错误，默认折叠可展开）。
- 消息流：气泡列表；**agent 消息渲染 blocks**：markdown、表格、代码块（高亮+复制）、产出物卡片、审批卡片、会议决策卡、工具事件折叠行（"🧰 调用了 cmd_run…" 可展开审计详情）。
- 思考过程（thought）默认折叠灰字，点击展开。
- 流式输出：打字机追加 + "正在思考…"光标 + 气泡尾部**「停止生成」**按钮（D17-⑥：点击停当前回合输出，队列保留，不标记完成）；回合未完成（重启中断）显示"（未完成）"补全按钮。
- **未完成回合恢复横幅（D17-⑤）**：打开项目/重连时，对有缺 turn_end 回合的会话在会话列表标「未完成」点；进入该会话顶部显示横幅卡片，三选：让 Agent **汇报中断点**（依据 plan 事件说明上次进行到第几步）/ **继续执行** / **忽略**。非推送打扰（仅在打开时出现一次）；与文本半截消息的补全按钮统一为恢复入口。
- **会话挂起预告横幅（D17-⑦）**：某成员将被会议占用（proposed→open 后即将入会）或正处于会议中时，其 user 会话顶部提示"TA 将于会议开始后被挂起，你的消息会排队，散会后继续处理"，设定期望、避免"突然消失"。
- 输入框：文本 + Enter 发送、Shift+Enter 换行；支持 @提及当前会话成员（P1）；发送后滚动到底；用户消息立即入队若 Agent busy 提示"该成员正在会议/工作中，消息已排队"。
- 会议视图：见 §4；审批卡片见 §5。

**右栏 Tab**
1. **会话列表**：分组 ①我的会话（每角色一条 user 会话，含未读点；**缺 turn_end 的会话标「未完成」点**，D17-⑤；停用实例置灰只读）②会议（进行中[含决策阻塞等拍板]/邀请中/排队中/已结束——对应 open·blocked_waiting_user / proposed / queued / closed，D16-①；排队中显示积压顺序与数量「排队中(n)」且**可取消**，D17-②；已结束显示纪要入口）。点击切换中栏。
2. **产出物**：manifest 列表（类型图标/标题/署名/版本/时间/状态/文件数/diff 摘要），操作：查看文件清单/回退/（策略要求时）审批。
3. **任务**：待办卡片列表，按受派者过滤；**状态流转按钮默认由用户操作（乙模式，D15）**：新建任务（指派给角色，来源可挂会议/产出物）、标记 in_progress/done/blocked/**终止**。**激活规则（D17-①）**：每 Agent 至多 1 个 in_progress——已有 in_progress 任务时，其他任务置 in_progress 的按钮被拦并提示"先等待当前任务完成或终止后再切换"（可先置 todo 排队；**无自动回退**）。**终止**：带确认；存在未结算改动时提示"将先结算为一条提交快照再标记已终止"（一键确认即结算+终止，可回退）；Agent 执行中终止显示"到当前可中断点生效"。
4. **记忆**：只读浏览（D14 评审定稿/M13）——分组：项目全局 / 按角色；条目列表（类型/时间/来源跳转）；P1 支持钉住/编辑/删除（FR-19）。
5. **项目信息**：workdir 路径（含"重设/打开目录"）、角色模板列表、审批策略开关、日志导出。

## 3. 状态与实时更新

- WS 事件驱动更新（会话流追加、Agent 状态徽标、审批出现、会议事件）。连接断开显示横幅并自动重连，重连后拉取增量（lastSeq）。
- 「需你处理」待办条由 `meeting.event`（决策阻塞/入会征询）/`approval.requested`（高危命令）驱动：出现即入条、原地处理后即移除，阻塞解除与会话状态同步一致（D17-③）。
- 未读/红点按会话维护（服务端下发 lastSeq，前端比较本地游标）。

## 4. 会议界面（对应 meetings.md）

- 顶部会议条：主题/主持人/成员头像(meeting 状态，含"邀请中/成员自主决定中"徽标，D14-⑤)/议程项进度条。
- 发言轮区：主持人"发问→成员依次发言→追问"，每轮一组卡片带轮次号；用户插话气泡左侧标记"插话"。
- **决策卡**：醒目边框：问题 + 选项按钮 + "自定义输入"；拍板后折叠成"已拍板：结论"，并记录决策者=用户；会议进入 blocked 时本卡同步进入顶部「需你处理」待办条**第一优先级**（可原地拍板，D17-③）。
- **转台与通知（D17-②）**：proposed 阶段静默可见不打扰（仅右栏"邀请中"状态）；**proposed→open 强通知**——顶部横幅"会议已开始，成员已入会"；**open→blocked_waiting_user** 高亮会议卡并进待办条。成员接受/拒绝/稍后聚合为一条**「会议阵容」消息**（谁在会/谁稍后+理由/谁拒绝+理由），用户可对阵容内成员强制接受/拒绝、会议中"召离"成员。
- 底部操作：主持人："发起下一议程 / 追问成员 / 总结并结束"；用户："结束会议 / 离会(不可，恒在会)"（用户发起会议见 U5，MVP 后）。已有会议进行中时新发起显示"排队中"并可取消（D17-②）。
- 会议纪要视图：结束自动刷新，右侧"纪要"抽屉结构化展示（主题/结论/待办/未决），待办可勾选转任务——**一步化（D17-⑦）**：勾选即建（标题=待办摘要、受派者预填纪要归属可改、来源自动挂本会议、creator=user）。

## 5. 审批卡片（高危命令/策略提交）

- 弹出卡片：类型徽标(高危命令/产出物提交) + 摘要（命令原文或文件清单与 diff 统计）+ 展开详情 + 来源会话链接；doc 类提交审批附**只读内容预览**（文本=内容预览；二进制/设计稿=文件信息+大小，D16-⑥）。
- 按钮：批准 / 拒绝（拒绝建议填写原因，可选，B3）。决策结果回注 Agent 并关闭卡片。
- **分级呈现（D17-④）**：高危命令 = **强打断**（全局横幅、写明命令与后果、不可批量）；doc 类提交 = 静默**托盘**"待确认提交 (n)"（右栏角标+折叠列表，不弹窗打断当前操作），托盘内可多选一次同意/拒绝（拒绝原因填写一次）。
- **信任开关（D17-④）**：doc 审批卡提供"同意并记住：本会话内该角色 doc 提交直接通过"；**默认信任范围仅 doc/test 报告类，config/deploy 脚本类不放行**（仍逐条审批）；撤销入口在项目信息页，撤销后恢复逐条审批。
- 审批来源多会话并存时全局聚合（同一审批只显示一次，所有相关会话同步状态）。

## 6. 组件与代码约定

- 目录：`web/src/{pages,components,stores,api,ws,styles}`；按域分组件目录（chat/meeting/artifact/team/approval/…）。
- 所有服务端事件均有 TS 类型；消息 blocks 渲染器是核心扩展点（新增产出物类型/卡片=注册 renderer）。
- 交互一致：列表 hover 反馈、危险操作二次确认、空状态插画文案、加载骨架。
- 可访问性基础：焦点可见、按钮有 label、气泡区 aria-live（P1 完善）。
