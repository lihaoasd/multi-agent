# 会议机制设计 · Agent Haness

> 类别：design · 状态：草稿(待评审) · 决策依据：D2（异步推进/需用户拍板时阻塞/用户可插话）、prd FR-09、US-5/6
> 关联：[sessions.md](sessions.md)、[agent-runtime.md](agent-runtime.md)、[memory.md](memory.md)

## 1. 定位与铁律

- 会议是 **Agent 发起**的多人沟通会话；**用户恒为成员**（不能缺席）；发起者 = **主持人**。
- **会议中只能沟通，不能执行产出性工作**（D14-⑩）：工具集降级——仅允许读取/检索/记忆/发言（fs 读 workdir+ro://、ws_read 本人私有区、session_search、memory_search、memory_append own），主持人可推进/结束议程；禁止提交产出物、禁止对工作目录写文件、禁止命令执行与审批。
- 会议**异步推进**：不要求全员"同时在线"，按轮次排队发言；需要用户决策时**阻塞等待**，用户答复后继续。
- 用户可随时**插话**（不等轮次）。

## 2. 会议生命周期与槽位（D16-①）

```
发起：无占槽会议 → proposed；有占槽会议 → queued（排队，槽空自动转 proposed，会话已落盘可恢复）
queued → proposed（邀请征询，占槽）
proposed → open：主持人开场白(议题/议程/目标) → 轮次驱动
open ⇄ blocked_waiting_user：某决策点需用户拍板（阻塞整个会议）
      └ 用户答复/拍板 → open 继续
open → closed：主持人或用户结束 → 自动生成纪要并回写记忆
```

参与者约束：
- 主持人 = 发起 Agent。**proposed 征询期主持人暂回 user 会话工作（不占）**（左栏显示「主持征询中」弱标签，hover 显示邀请进度，D17-⑦）；≥1 名成员接受转 open 后主持人正式入会（Agent 状态 meeting）并持续占用直到散会（MVP 由主持人或用户结束；主持转让为后续版本）。
- 成员 Agent 入会 = 挂起其个人会话（user 会话显示 suspended——occupancy 派生，D18-④，单工 D11）；被邀请时**自主决定**（D14-⑤）：先完成当前回合到可中断点再入会（被抢占的 plan-execute 由 dispatcher 依据 plan 事件在散会后同一会话内续跑，D16-③）。
- 用户：随时进出（UI 层不阻塞）；但**决策点必须用户答复**才能放行。
- **MVP 并发上限（D14-⑥）**：同一项目同时至多 1 个**占槽**会议（proposed/open/blocked_waiting_user 均占槽）；占用中时新发起落 `queued` 排队（持久化、重启可恢复），当前会议结束/取消后自动转 proposed。
- **queued/proposed 可取消（D17-②）**：发起者或用户均可取消排队/征询中的会议（直接关闭该会议会话并通知相关方），避免重启恢复后残留僵尸排队项；UI 对排队会议显示积压顺序与数量「排队中(n)」。
- **转台通知分级（D17-②）**：`queued→proposed` 静默可见不打扰（仅右栏状态变化）；`proposed→open` **强通知**（横幅「会议已开始，成员已入会」）；`open→blocked_waiting_user` **最强打扰**，并进入顶部「需你处理」待办条第一优先级（UI 呈现见 frontend/style.md）。
- 占槽会议若长期停在 blocked_waiting_user 等用户，将阻塞后续会议与相关 Agent——UI 提供"挂起会议"缓解（见 §5）。

## 3. 发起与邀请

1. 任一 Agent 在合适时机调用 `meeting_start`（或 PM 依里程碑/协调需要发起）：填写主题、目标、议程项、候选成员(≥1 Agent)、期望产出。
2. 系统创建 meeting 会话（state=`proposed`；用户自动成为成员，看到邀请卡片）；已有占槽会议时本次发起落 `queued` 排队（槽空自动转 proposed，D14-⑥/D16-①，会话文件已落盘、重启可恢复）。
3. **成员自主入会（D14-⑤）**：系统向成员 Agent 发起入会征询，成员在自身回合评估当前工作后决定 `接受 / 稍后加入 / 拒绝`（拒绝/稍后要写理由）——接受=暂停当前任务到可中断点入会；决定与理由写入会议记录并**聚合为一条「会议阵容」消息推送给用户**（谁在会 / 谁稍后+理由 / 谁拒绝+理由，不逐条打扰，D17-②）。**用户可随时干预**：对阵容内成员强制接受/拒绝、或在会议中"召离"成员。
4. 至少 1 名成员接受后会议 open；全部拒绝则由主持人决定取消。

发起场景建议（内置惯例，非强制）：
- 需求澄清会（PM/产品 主持，相关角色参加）；
- 技术评审会（架构 主持，dev/qa/ops 参加）；
- 阶段例会（PM 主持，全体成员），用于拆任务与对齐。

## 4. 轮次引擎（异步驱动核心）

会议消息分两类通道，**互不阻塞**：

1. **议程轮次（主持人驱动）**：
   - 主持人把一个议程项"发问"→ 系统按成员顺序逐个让其发言（每个成员的发言经 dispatcher 排队，等该 Agent 空闲可中断点）。
   - 成员发言后主持人可追问/要求补充（追问算新一轮）。
   - 主持人判定该议程达成共识/结论 → 记录结论 → 进入下一议程。
2. **自由插话（用户 或 成员）**：
   - 用户随时发言（插话优先显示，不打断当前发言者生成，但会让主持人把它纳入当前/下一议程）。
   - 成员也可补充，但非轮次发言需主持人"点名/认可"避免多人抢话（实现为简单队列+主持人控制，不做复杂仲裁）。

轮次状态与超时：成员发言无时间上限但有轮询控制（超时后主持人可跳过并记录）。

## 5. 用户决策点（阻塞语义，D2 核心）

主持人或成员发言中出现**需要用户拍板**的内容（改需求范围/选技术方案/定优先级/批准资源等）时：

1. **主持人**调用 `meeting_ask_user{question, options?}`（meeting 会话内工具、**仅主持人**可调，D18-①）；成员发言中出现需要用户拍板的内容时，先请主持人升格后由其触发。
2. 会议进入 `blocked_waiting_user`，**整个会议轮次暂停**（其余成员等待，不产生新的发言轮）；个人会话挂起照旧。**同一时刻至多 1 个 pending 决策点**（旧决策点未解除时新的请求被拒并提示）。
3. 系统把决策卡片推送给用户（会议窗口内高亮 + 进入顶部「需你处理」待办条**第一优先级**，D17-③；待办条可原地拍板或一键跳到本会议）。
4. 用户答复（选择/文字）→ 决策结果作为消息回到会议 → 主持人/发言人继续。
   - 若用户只是"插话"非正式答复，主持人可澄清"是否需要我现在拍板"。
5. 超时策略（可配置）：默认无限等待（本地个人使用），提供"挂起会议"（用户主动暂停，稍后回来继续）。

> 与 user 会话的区别：user 会话 Agent 忙时只是排队（用户不等也无碍）；会议决策点是**显式闸门**，卡住全体推进。

## 6. 会议期间 Agent 状态与个人工作

- 主持人/成员 Agent：`meeting` 状态，个人会话挂起（队列保留）。
- 会议 blocked 等用户时：成员保持 meeting 状态等待（不释放去干个人活——保证"会中人只开会"）。
- 用户可中途对某成员说"你先去忙 X，会开完叫你"→ 成员可申请离会（主持人同意/用户直接同意）后回到个人会话。
- **散会后恢复与自主调整（D14-⑤）**：会议结束/成员离会后，成员回到个人会话继续队列中原任务；依据会议纪要与会话结论**自主评估当前工作是否受影响**（范围/优先级/方案），需要调整时更新自己的安排——以会话汇报 + 角色记忆记录调整决定（决定全程留痕、用户可见）。涉及正式任务状态/产出变更：乙模式下经用户在 UI 确认，甲模式（task.assignByAgent 开启）可由工具驱动（D15）。

## 7. 结束与纪要回写（US-6）

结束触发方：主持人（"总结并结束"）或用户（"结束会议"）。
自动流程：
1. 摘要引擎读取会议全量日志（含各议程结论、用户决策）生成**会议纪要**（结构化：主题/参与/议程结论/待办/未决）。
2. 纪要写入：
   - 每个参与者（含主持人）的**角色记忆**（type=meeting_summary，含其相关待办）；
   - **项目全局记忆**（决策/结论登记）；
   - 会议 log 尾部 `summary` 事件。
3. UI 右栏"会议纪要"可回看；纪要内的待办由**用户**点击转出为 tasks——**一步化（D17-⑦）**：勾选即建，标题=待办摘要、受派者预填纪要归属（可改）、来源自动挂本会议、creator=user（Agent 经工具直接建任务仅存在于甲模式，D15）。

> **纪要=可重放派生视图（D18-⑤b）**：close 流程先置 `minutesPending` 标记再调用纪要生成器；生成基于 closed 会话**全量日志**、幂等可重跑，引擎失败/进程重启不丢纪要（UI 提供"重新生成纪要"）。

## 8. 会议中的工具降级清单（D14-⑩ / H4）

会议会话内 agent 可用工具：
- 读取/检索类：`fs_read_file`/`fs_list_dir`/`fs_search`（**只读 workdir+ro://**）、`ws_read`（**本人私有区**）、`session_search`、`memory_search`、`memory_append`（仅 own）
- 主持人专用：`meeting_advance`、`meeting_close`、`meeting_ask_user`（校验 = 会话类型 meeting + 调用者是主持人，D18-①）

禁用（产出/执行/审批类一律不可用）：`ws_write`、`workdir_edit`、`cmd_run`、`artifact_submit`、`artifact_rollback`、`approval_query`、`meeting_start`、`task_*`（默认）。

（实现：loop runner 的工具可用性校验 = 角色白名单 × 会话类型 × 主持人身份，见 tools.md §3。）

## 9. UI 呈现（详见 frontend/style.md）

- 会话窗口顶部会议条：主题/主持人/成员(带状态)/议程进度。
- 轮次区：每个"发言轮"为一组卡片；用户插话高亮。
- 决策卡片：选项按钮 + 自定义输入；确认后折叠为"已拍板：xxx"。
- 结束按钮：主持人/用户可用；结束前弹确认（未完成议程提示）。

## 10. 边界与未决

- MVP 不做：语音/视频、多人同时输入仲裁外的复杂协商、会议录制回放。
- U5：MVP 后支持"用户发起会议"（当前需求中会议由 Agent 发起）。
