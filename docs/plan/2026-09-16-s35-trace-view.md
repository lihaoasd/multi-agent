# S35 方案：会话窗口加「详细日志（trace）」视图（可切换）

> 日期：2026-09-16　类型：用户指令（"会话窗口，加一个 trace 日志查看，切换窗口详细日志"）　真源：`design/ui.md` §4、`prd.md` FR-30
> 关联：`docs/changes/2026-09-16-s35-trace-view.md`、`docs/plan/development.md`

## 1 需求

用户口径：**在会话窗口加一个 trace 日志查看，能切换窗口看详细日志。**

| # | 需求 | 验收 |
| --- | --- | --- |
| R1 | 会话卡片头部有**视图切换** | `Segmented`：`对话`（默认）/ `详细日志` |
| R2 | **详细日志 = 原始事件全量** | 列出该会话**所有 kind**（含 `plan`/`turn_start`/`turn_end`/`state`/`summary`/`artifact`/`approval_*`），每行头部为 `#seq · 时间 · turn · kind`，下方是可读摘要 |
| R3 | 需要时能看**原始 payload** | 详细日志模式下出现一个开关（`Switch`）：打开后每行附加格式化 JSON |
| R4 | 对话视图不变 | 仍是 S22/S26/S28/S34 的口径（消息/思考/工具调用+折叠参数/结果/错误），详细日志是**另一个窗口**，不影响它 |
| R5 | 跟随滚动仍然生效 | 切换视图、展开 payload 时也保持"贴底跟随"（S34 的策略不变） |
| R6 | 不改后端 | 复用 `GET /sessions/:sid`（首屏 200 条）与 WS 增量；接口契约不变 |

## 2 现状与影响面

| 面 | 位置 | 现状（S34 之后） |
| --- | --- | --- |
| 会话窗口 | `web/src/pages/SessionPanel.tsx` | 只有"对话"一种视图：`visibleEvents` 过滤成五类；`plan`/`turn` 边界/`state`/`summary` 等**在界面上完全看不到** |
| 事件读取 | `web/src/api/sessions.ts` | `detail(projectId, sessionId, 200)` 已返回**全部**事件（含未展示的 kind）——数据现成，只是没渲染 |
| 渲染规则 | `web/src/lib/event-display.ts` | `eventRow` 面向"对话视图"（五类）；缺一个覆盖**全部 kind** 的"详细日志行"规则 |
| 后端 | — | **本轮不改** |

## 3 关键决定

1. **两个视图而不是"再加筛选"**：S22 已按用户口径删掉 kind 筛选下拉；现在要"看完整日志"的正确形态是**换窗口**（`对话` / `详细日志`），而不是把筛选下拉请回来。
2. **详细日志覆盖全部 kind 且摘要可读**：新增纯函数 `traceLine(event) → { head, text }`——头部 `#seq · HH:MM:SS.mmm · turn N · kind`，摘要把每类事件说清（`plan` 带状态与步数、`turn_start` 带 loop、`state` 直接给 JSON、工具结果标注成功/失败…）。
3. **原始 payload 用开关而不是默认展开**：默认只给摘要（可读性优先），需要排查时打开开关看完整 JSON（避免 200 行 JSON 把窗口淹没）。
4. **纯函数先行**：`traceLine` 可被 node 侧单测覆盖（延续 S23/S26/S28/S30/S33 的做法），界面只做映射。
5. **复用既有滚动策略**：跟随 effect 的依赖加上 `viewMode` / `showRawPayload`，切视图与展开 payload 后仍贴底。
6. **不动"对话"视图与后端**：本轮是**新增一个观察窗口**，不改变既有交互。

## 4 实现步骤

- `web/src/lib/event-display.ts`：`EventLike` 增可选 `ts`；新增 `shortTime(ts)` 与 **`traceLine(event)`**（覆盖 `message`/`thought`/`tool_call`/`tool_result`/`turn_start`/`turn_end`/`plan`/`summary`/`artifact`/`approval_request`/`approval_result`/`state`/`error`/兜底）。
- `web/src/pages/SessionPanel.tsx`：新增 `viewMode`（`chat`/`trace`，默认对话）与 `showRawPayload`；头部 `extra` 最前面放 `Segmented`，详细日志模式下再显示 payload 开关；消息区内按视图分支渲染（详细日志走 `events` 全量 + `traceLine`）；滚动 effect 依赖补 `viewMode`/`showRawPayload`。
- `tests/unit/web/event-display.test.ts`：新增"详细日志行"用例（message/plan/turn_start/turn_end/state/工具成功与失败/时间戳缺失）。
- 文档回写：`prd` **D38** + FR-30 补注、`ui.md` §4、`README.md`/`plan/development.md`/`testing/plan.md`、验收阶段清单加 `s35`。

## 6 风险

| 风险 | 对策 |
| --- | --- |
| 详细日志一次 200 条 DOM 变多 | 行样式极轻（无折叠组件、无 Markdown）；payload JSON 只在开关打开时渲染 |
| 摘要遗漏 payload 关键信息 | 提供原始 payload 开关兜底；`traceLine` 的兜底分支对未知 kind 直接给 JSON |
| 与"对话视图"口径混淆 | 两个视图互斥渲染；`ui.md` §4 与 prd D38 写明"对话=阅读视图（五类）、详细日志=原始事件全量（可展开 payload）" |
| 切视图后位置跳动 | 跟随 effect 把 `viewMode`/`showRawPayload` 纳入依赖，切换后贴底 |
