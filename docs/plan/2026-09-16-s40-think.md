# S40 方案：开启 think（思考模式）并在会话里显示思考

> 日期：2026-09-16　类型：用户口径（"think开启了吗，要开启think，页面也要显示出来"）　真源：`design/model-config.md`、`design/agent-runtime.md` §3、`design/ui.md` §4、`prd.md` FR-10 / FR-30
> 关联：`docs/changes/2026-09-16-s40-think.md`、`docs/plan/development.md`

## 1 需求

用户口径：**think 开了吗；要开 think；页面也要把思考显示出来。**

| # | 需求 | 验收 |
| --- | --- | --- |
| R1 | 能**开关** think | 模型条目行有「思考」开关（新增表单也有勾选）；开启后 `capabilities` 含 `reasoning`，界面能看见 |
| R2 | 开启后**请求真的带思考参数** | 四种协议各按自己的参数名下发（见 §3-①）；不开启则**完全不发**（陌生参数会被部分厂商 400） |
| R3 | 模型返回的思考**必须落进会话** | 所有策略、**每一轮**（含工具循环、plan-execute 的制定计划与每一步）都产出 `thought` 事件 |
| R4 | 页面（会话流）**显示思考** | 「思考」条目可见（S22/S26/D31 的口径不变：思考是等宽纯文本、直接展示） |
| R5 | **思考要回传** | assistant 消息带上 `reasoning`，openai-compatible 按 `reasoning_content` 回传——DeepSeek 带 `tools` 时**不回传会 400** |
| R6 | 事件模型与接口不变 | `thought` 事件早已存在，不新增 kind、不新增依赖 |

## 2 现状与根因（含实测）

**实测本机 `data/`（10 个会话日志、198 条事件）**：`thought` **0 条**，而 `plan` 16 条、`tool_call` 74 条 —— 思考链路在真实运行里从未落地。

| # | 位置 | 问题 |
| --- | --- | --- |
| A | `src/application/agent-loop/strategies.ts` | `emitThought` 只在 `direct` 的**首次**调用、`reflective` 的自查/修订调用上调用。**`plan-execute` 一条都不发**（而内置模板默认就是 plan-execute），`runToolLoop` 的多轮思考也全部丢弃 → 页面上永远看不到思考 |
| B | `src/infra/model/providers/*.ts` | **请求侧从不带思考参数**：`capabilities.reasoning` 只是登记值、运行期无人消费；Anthropic（需 `thinking`）、Gemini（需 `thinkingConfig.includeThoughts`）、Ollama（需顶层 `think`）因此永远不会思考 |
| C | `src/infra/model/providers/openai-compatible.ts` + `strategies.withToolResults` | **思考不回传**：[DeepSeek 文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)明确"带 `tools` 的请求，后续所有请求必须完整回传 `reasoning_content`，否则 API 会返回 400 报错"；我们连 `reasoning` 都没放进 assistant 消息 |

旁证：`p_mu7rs071omcf1` 的架构师会话有两次 `ERR_MODEL`，都是 **60s 超时**（turn 2/3）——思考模式会显著变慢，超时预算是配置问题（见 §6）。

## 3 关键决定

1. **能力标记驱动请求参数**（勾选＝用户确认该模型支持该协议参数，避免乱发被 400）：
   | 协议 | 开启思考时下发 |
   | --- | --- |
   | `openai-compatible`（DeepSeek/OpenAI 系） | `reasoning_effort: "high"`（可由 `defaultParams.reasoningEffort` 改 low/high/max） |
   | `anthropic` | `thinking: { type: 'enabled', budget_tokens }`（预算取 `defaultParams.thinkingBudget`，夹在 `max_tokens - 1024` 之内），**仅在本次请求不带 tools 时**（见 ④） |
   | `gemini` | `generationConfig.thinkingConfig.includeThoughts = true`（可选 `thinkingBudget`） |
   | `ollama` | 顶层 `think: true` |
2. **开关必须用户可操作**：模型条目行加「思考」开关（`updateModel({capabilities})`）、新增条目表单加勾选（后端 API 早已支持 `capabilities`，此前只有"渲染标签"没有"改"的入口）。
3. **回传不受开关限制**：能力只管"要不要**主动要求**思考"；**拿到的思考一律回传**——DeepSeek 思考模式默认就是开的，模型可能自己就思考了，少回传就会被拒。
4. **Anthropic 带 tools 时不发 thinking**：其思考块（含 `signature`）在后续带工具调用时必须原样回传，本平台尚未保存 signature；宁可"无工具调用时才思考"，也不把 400 引进来。完整支持＝保存 signature 并回传，记入遗留。
5. **思考按轮次独立落事件**：每轮一条 `thought`（不再合并成一大坨），方便与 `tool_call`/`turn` 对照排查。
6. **不新增依赖、不改事件模型**：`thought` 事件与 UI 条目早已存在（S22/S26），本轮补的是"生产端"。

## 4 实现步骤

- `src/ports/model.ts`：`ChatMessage` 增 `reasoning?`（思考随 assistant 消息回传的载体）。
- `src/ports/model-config.ts`：`defaultParams` 增 `reasoningEffort`（low/high/max）与 `thinkingBudget`。
- `src/application/agent-loop/strategies.ts`：`withToolResults(..., reasoning?)` 把思考挂到 assistant 消息；`runToolLoop` 每轮 `emitThought`；`direct`/`reflective` 的初稿与修订也落地；**plan-execute** 的制定计划调用与每一步调用都落地。
- 四个适配器：按 §3-① 下发思考参数；openai-compatible 在 assistant 消息上回传 `reasoning_content`。
- `web/src/pages/ModelModule.tsx`：模型条目行「思考」开关 + 新增表单勾选（→ `capabilities` 含 `reasoning`）。
- 测试：`tests/unit/infra/model-adapters.test.ts`（四种协议的思考参数 + 回传/不回传边界）、`tests/unit/application/loop-strategies.test.ts`（每轮思考落地 + 回传 + plan-execute 思考）。
- 文档回写：`prd` **D43** + FR-10/FR-30 补注、`model-config.md`（能力→参数映射、回传要求、超时提示）、`agent-runtime.md` §3、`ui.md` §3/§4、`README.md`/`plan/development.md`/`testing/plan.md`、验收阶段清单加 `s40`。

## 5 验证方式

| 层 | 手段 |
| --- | --- |
| 单测（适配器） | openai-compatible：勾选 → `reasoning_effort` + assistant 消息 `reasoning_content`；不勾选 → **无** `reasoning_effort`，但**仍回传**已拿到的思考。anthropic：无 tools 发 `thinking`（budget 夹在 max_tokens 内）、带 tools 不发。gemini：`thinkingConfig.includeThoughts`。ollama：`think: true` |
| 单测（策略） | `direct`：两轮思考都落 `thought`，且第二轮请求的 assistant 消息带 `reasoning`；`plan-execute`：制定计划 + 每一步共 3 条思考；`reflective`：自查意见 + 自查思考 |
| 回归 | `npm test` 全绿 + `coverage` 142/142 + `ratchet` 0 + `typecheck`/`eslint` + `npm run build` |
| **用户点验** | ① 模型页把 `deepseek-flash` 的「思考」打开 ② 让任一 Agent 干一件事 ③ 会话流里出现「思考」条目（有内容），详细日志里能看到 `thought` 行 ④ 多轮工具调用不再出现 400 |

## 6 风险

| 风险 | 对策 |
| --- | --- |
| 陌生思考参数被厂商 400 | 只在**模型条目显式勾选**时下发；不勾选完全不发（默认零风险） |
| DeepSeek 带 tools 时缺 `reasoning_content` → 400 | 有思考就回传（不受开关限制）+ 单测钉住 |
| Anthropic 思考 + 工具调用需要 signature 回传 | 本轮带 tools 时不发 thinking（宁缺勿错），完整支持记遗留 |
| 思考让回合变慢、撞上 60s 超时（实测已发生 2 次） | 在文档与回复里明确提示：可在供应商配置里调大「超时（毫秒）」；本轮不改默认值（避免影响其它供应商） |
| 思考内容很长刷屏 | 思考条目是纯文本、无 Markdown；如觉吵，可在会话流做默认折叠（属新交互，未做） |
