# S57 方案：「任务与产出物」用户只读（不派单、不改状态）

> 日期：2026-09-21　类型：用户口径（"任务与产出物里，用户不能派单和修改任务状态"）　真源：`prd` FR-08、`ui.md` §5、`agent-runtime.md` §6
> 关联：`docs/changes/2026-09-21-s57-task-panel-readonly.md`、`docs/plan/development.md`
> 用户原话：**"任务与产出物里，用户不能派单和修改任务状态"**

## 1 需求确认

这句话有两种读法（"点了没生效" vs "不该让用户做"）。先问了一句，用户选择：

> **去掉这两个入口：用户只读（不能派单、不能改状态），任务由 PM/角色推进。**

即：**「任务与产出物」只做"看得见"**——派发与状态流转完全由角色驱动（PM 按职能派单 → 受派人 `task_claim` → 执行 → `task_update` 汇报），老板不再在这个面板里点。这与 S50/D53「产品经理按角色职能制定任务并分派」、S56/D60「产出物表只读」是同一条口径的延续：**面板是观察窗，不是操作台**。

（顺带说明为什么不是"修好入口"：`POST /tasks` 与 `PATCH /tasks/:tid` 两条接口都正常，派单下拉能拿到 8 个启用角色，用户项目里 15 条任务全部是 `creator=pm_1` —— 复现不出"点了没生效"。）

## 2 改动

| # | 改动 | 落点 |
| --- | --- | --- |
| ① | **去掉「派单」入口** | `web/src/pages/WorkPanel.tsx`：删「派单」按钮、派单 Modal（受派人/标题/说明表单）、`assignOpen`/`assignForm`/`members` 状态与 `Form`/`Input`/`Modal`/`Select` 依赖；`load()` 不再拉 `projectApi.listTeam`（少一次请求） |
| ② | **去掉改状态入口** | 删任务表「操作」列（状态下拉）、`changeTaskState`/`applyTaskState`（含单工槽位"收口它并开工"确认）、`message` 使用；任务表只留「任务/受派/发起/状态/产出物/备注」 |
| ③ | **删掉只为该入口存在的纯逻辑** | 删 `web/src/lib/task-state.ts`（`taskStateOptions`/`holdingTaskOf`）与其 4 条单测 |
| ④ | **说明写进面板** | 任务卡顶部一行灰字：**"任务由角色按职能派发与推进（派单走 PM、领取/汇报走受派人）；本面板只读，人工干预请用 API。"**——避免"派单按钮去哪了"的疑惑 |
| ⑤ | **接口与权限不动** | `POST /api/projects/:pid/tasks`、`PATCH /api/projects/:pid/tasks/:tid` 保留；服务端 `actor='user'` 的宽松迁移（S55/D59）与"激活即唤醒"也保留，供脚本/人工干预（面板不再使用它们） |

**不改**：右栏任务列表（本来就是只读）、询问/审批的落点、产出物表（S56 起只读）、`workApi.createTask`/`setTaskState` 客户端方法（留作脚本参考）、服务端任务状态机与单工槽位。

## 3 验证方式

| 层 | 手段 |
| --- | --- |
| 静态 | `typecheck` + `eslint` 无未使用导入/变量残留（`Form`/`Input`/`Modal`/`Select`/`message`/`ApiError`/`projectApi` 均已清理） |
| 界面（人验） | 「任务与产出物」：任务卡只剩「刷新」按钮；表格无「操作」列；面板顶部有只读说明；产出物/署名表不变 |
| 回归 | 全量 `npm test` / `coverage` 143/143 / `ratchet` 0 / `build` 全绿；删掉的只有 `tests/unit/web/task-state.test.ts`（4 条，随功能一起删） |
| 接口未受影响 | `POST /tasks`、`PATCH /tasks/:tid` 的既有单测/集成用例全绿（S55 的 `actor='user'` 任意迁移与激活唤醒用例保留） |
| **用户点验** | 面板里**没有**「派单」按钮、**没有**状态下拉；要开工就同 PM 会话里说（PM 会 `task_assign`），要看进度就看这个面板 |

## 4 风险

| 风险 | 对策 |
| --- | --- |
| 老板想临时插一条任务却没入口 | ① 同 PM（或对应角色）会话里说一句，让它派单（这也是原本的设计意图）；② 仍可用 API/脚本。面板顶部的说明把这两条讲清楚了 |
| 有人以为"任务功能坏了" | 说明文字点明"由角色驱动 + 只读"；README/`ui.md` 同步口径 |
| 之前 S55 的“面板可改”行为被撤销后留下死代码 | `web/src/lib/task-state.ts` 与服务端都复核过：纯逻辑文件已删；服务端保留是有意为之（API 能力），文档写明"面板不再使用" |
| 关键能力被误删（回退/审批等） | 本次只动 `WorkPanel` 的派单与改状态；产出物、询问、署名表逐行复核未改 |
