| 在范围内 | 不在范围内 |

## 2. 关键决定

1. **服务端运行方式**：`npm start` 用 `tsx` 直跑 TS；`npm run build` = 服务端类型检查 + 前端构建。因此**不产出服务端 `dist`**，development.md 原列的 `tsconfig.build.json` 取消（避免"编译产物 + tsx 直跑"两套口径并存）。
2. **依赖版本以本机已安装为准**：React 19.3 + antd 6.6 + Vite 8 + Vitest 5 + TypeScript 6 + ESLint 10；设计文档原写"React 18 + antd 5"，已回写 `architecture.md` §2 与 `ui.md` §1（不引新依赖，符合 abstraction §5.1）。
3. **DI 容器释放语义**：`singleton` 只在**根容器** dispose 时释放；`scoped`/`transient` 随其所在容器释放。作用域 dispose **不得**清空共享 singleton 的释放队列（首版实测踩到，已修并有回归用例）。
4. **门禁实现**：ESLint `no-restricted-imports` zones（越层即失败）+ ratchet 基线 `tools/import-ratchet.json`（只减不增）。ratchet 用 **ESLint Node API** 而非子进程，避免受限环境下的 piped stdio 限制。
5. **静态资源与 404**：`web/dist` 存在才注册 `@fastify/static` 与 SPA 回退，否则纯 API 模式 + JSON 404。Fastify 每个 prefix **只允许一个 notFound handler**，故错误处理与 SPA 回退分工在 `errors.ts` / `static.ts`（首版重复注册导致启动失败，已修并有集成用例）。
6. **npm cache 固定在工作区内**：`.npmrc` 声明 `cache=.npm-cache`，并在文件内说明本机 `npm_config_cache` 环境变量优先级更高、受限沙箱下需显式覆盖。
