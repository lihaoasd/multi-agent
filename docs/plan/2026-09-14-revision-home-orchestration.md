## 1. 需求（用户原文要点）

1. **首页有工具模块**：同类工具包装成"包"，展示各包；用户可自制工具包（**MVP 只展示**，制作功能后续）。
2. **首页有 Agent 模块**：Agent 列表，可见 **loop / 提示词 / 工具 / 模型**，用户可配置这四项（**MVP 只展示**，提交配置后续）；默认预置当前软件团队 Agent，当前面向软件开发场景，后续扩展通用领域。
3. **首页有项目模块**：创建项目需选择项目目录；进入项目页后是两个导航——
   - **拓扑**：大画布展示 Agent 拓扑，可增删 Agent、用有向边连接（边 = 谁能给谁创建/委派任务），可编辑、保存；每个 Agent 是一张卡片；可观测总体工作情况。
   - **对话**：可切换每个角色的会话窗口，会话中显示 Agent 的工作日志。
   - **右栏**：任务列表、询问列表、审批列表，查看 Agent 工作时的任务执行状态。

## 2. 澄清结论（两轮问答，2026-09-14）

| 议题 | 结论 |
| --- | --- |
| 交付范围 | **只更新设计文档**，不动代码 |
| 连线语义 | **一种有向边**；运行期**强制只能沿出边创建/委派任务** |
| 画布深度 | 编辑 + 保存 + **节点实时状态徽标** |
| 询问列表 | **恢复** Agent→用户提问 + 阻塞等待（上一轮删除的机制回归） |
| 启动模型 | 用户选择某个 Agent 对话 **即表示启动**；**各 Agent 独立工作**；边只表示"可以创建委派的任务"；Agent 结束当前工作后**领取**任务继续执行 |
| 运行控制 | **只要暂停和停止**（不做项目级运行状态机，不做"开始运行"按钮） |
| 工具包 | **目前 7 个都是基础包**（全员必选）；可以把"带工具列表的包"添加到 Agent；细节后续详细讨论 |
| Agent 对象 | 首页展示**系统模板库 + 场景标签**（software 现成、general 预留） |
| 布局 | **拓扑页 2 栏**（左画布 + 右三列表）；**对话页 3 栏**（左会话切换 + 中会话 + 右三列表） |
| 待办聚合 | **不做**顶部"需要你处理"待办条，右栏询问/审批列表承载 |

## 3. 本次采用的判断（显式记录，可推翻）

1. **7 个基础包 = 现有 7 个工具域**：`fs`（文件读写）/ `cmd`（命令）/ `memory`（记忆）/ `session`（会话检索）/ `artifact`（产出物：受控编辑 `workdir_edit` + 登记/回退）/ `approval`（审批查询）/ `task`（任务）。`workdir_edit` 归入 `artifact` 包（写工作目录与产出登记同族）。
2. **包不改变现有授权链**：仍按"角色白名单 × 会话类型 × allowedRoots × 归属校验"判定；包是**展示与未来挂载单位**，MVP 全员挂 7 个基础包。
3. **不设项目级运行状态**：删除"开始运行"概念，改为"用户在会话中对话 = 该 Agent 开工"；控制只有 **Agent 级暂停/停止**。
   - 暂停 = 不再领新任务，当前回合执行到可中断点后挂起（沿用"待停用"边界语义）。
   - 停止 = 终止该 Agent 当前任务，走 D17-① 终止语义（存在未结算改动先结算为 code artifact 快照）。
4. **汇报沿反向**：边为有向"可委派"关系；任务完成/受阻的**汇报沿同一条边反向**回派发者，属系统行为、不算越权。反向**主动派单/沟通**（下游给上游派活）不允许。
5. **用户不受边约束**：用户（老板）可手动向任意 Agent 派单/终止/干预；边只约束 **Agent 发起的**委派。
6. **运行中可改拓扑**：因为不存在项目级运行态，边只影响"未来的委派"；编辑保存即对新派发生效（保存需通过校验：无自环、无重复边、节点必须是本项目实例）。
7. **画布技术选型**：React Flow（`@xyflow/react`）作为候选实现；本方案只定行为契约，选型在编码阶段定稿。
8. **补齐缺失文档**：新建 `docs/README.md`（术语表 + 文档地图 + 编号索引，同时修掉 PRD 的断链）与 `docs/design/ui.md`（信息架构/页面/交互，取代此前被删的 `frontend/style.md`）。

## 6. 验证方式

- **一致性**：新需求与既有口径无矛盾——特别是"任务派发"（D15 由乙模式改为 Agent 派发 + 边约束）、"询问机制"（恢复并作为 waiting 的来源之一）、"布局"（三栏 → 拓扑 2 栏 / 对话 3 栏）。
- **可追溯**：每条新 FR 都能指到本方案 §1/§2 的某一句需求。
- **引用完整**：新增文档进入文档地图；全库链接可解析（目标：断链从 3 处降到 0）。
- **术语统一**：编排图 / 工具包 / 询问 / 领取 / 暂停 / 停止 六个术语在 PRD、设计文档、UI 文档中同义同词。
- **测试可验**：`testing/plan.md` 覆盖边约束越权、询问阻塞、暂停/停止、画布保存校验。
