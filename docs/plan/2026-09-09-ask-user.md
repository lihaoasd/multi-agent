# 开发方案：角色向用户提问/确认/审批（单选·多选·确认·文本）· 2026-09-09

> 需求来源（用户口述）："角色需要用户询问，确认，审批交互，可以用户单选，多选等交互"

## 1. 现状

- 已有：高危命令/提交的**审批**（approvals.jsonl + 「需你处理」+ 顶部角标）与会议**拍板**（决策点）。
- 缺失：Agent 在 user 会话里**主动向用户提问**（确认 / 单选 / 多选 / 自由文本）的结构化交互；
  模型只能把问题写在正文里，用户回答也只是普通聊天，没有可点的选项、没有"待回答"状态与待办聚合。

## 2. 交互设计（不阻塞进程、可恢复）

延续平台既有模式（先盘后推 + 唤醒，同 D18-③ 任务唤醒）：

1. Agent 调用新工具 `ask_user{question, kind, options, allowText}` → 落一条**待回答**记录（questions.jsonl）；
   同一会话已有待回答问题时，再次提问被拒（防刷屏）。
2. 前端在会话窗口（输入框上方）渲染**问题卡片**：确认（确认/取消）、单选（radio）、多选（checkbox）、
   文本（输入框），可选附加说明；「需你处理」弹窗与角标同步计入（kind=question，一键跳转会话回答）。
3. 用户提交 → 记录 answered（校验选项合法性）→ 把答复作为一条**用户消息**写入该会话并**触发 Agent 回合**
   （复用 `sessionService.sendUserMessage`），Agent 据此继续；答复在会话里可见、可审计。
4. 不阻塞回合：提问回合正常结束；用户回答后开启新回合（刷新/重启都不丢，答案落盘）。

## 3. 改动范围

### A. 新服务 `src/application/question/question-service.ts`

- `QuestionRecord{id,projectId,sessionId,asker,question,kind,options,allowText,status,answer,createdAt,answeredAt}`
- `ask()`：kind 校验（confirm/single/multi/text；single/multi 需 ≥2 选项；confirm 默认「确认/取消」）；
  同会话已有 pending → ERR_CONFLICT。
- `answer()`：choice 必须 ∈ options；multi 非空且 ⊆ options；text 类必须有文本；已答 → ERR_CONFLICT。
- `list(projectId,{status?,sessionId?})` / `get()`；存储 `questions.jsonl`（原子写）。

### B. 工具接入

- `ToolEnv` 增加 `sessionId?`；`buildToolEnv(..., {sessionId})` 注入（loop 的 exec 传 `ctx.sessionId`）。
- `registerServiceTools` 注册 `ask_user`（availableIn:['user']，paramsSchema，描述要求"需要拍板/确认/选择时用"）。
- 角色模板（8 个内置 YAML）tools 增加 `ask_user`；组合根 `listTools` 对 user 会话**始终附带**平台能力工具
  `ask_user`（保证老项目快照也能用）。
- 系统提示：可用工具列表已列出；补充一句"需要用户拍板/确认/选择时调用 ask_user，不要替用户决定"。

### C. 待办聚合与路由

- `AttentionService` 增加 questions（kind:'question'，带 questionId）。
- `GET /api/projects/:pid/questions?status=&sessionId=`、`POST /api/projects/:pid/questions/:qid/answer`；
  回答成功 → 写用户消息 + 触发 Agent 回合（会话非 user 或角色停用时只落记录并返回提示）。

### D. 前端

- `index.html`：`#messages` 与 `#composer` 之间加 `#question-zone`。
- `app.js`：`refreshPanels()` 拉取 pending questions → `renderQuestions()` 渲染卡片（radio/checkbox/确认按钮/文本 +
  提交）；「需你处理」弹窗支持 question 项（一键跳到会话回答）。
- `style.css`：问题卡片样式。

### E. 测试/文档

- 新增 `tests/question-m8h.test.ts`：服务校验（非法选项/多选为空/文本必填/重复回答/并发提问被拒）、
  API 全链路（工具调用→问题待答→attention 计入→回答→用户消息落盘→Agent 回合继续）。
- `docs/changes/2026-09-09-ask-user.md` + README 同步。

## 4. 验证

- tsc / eslint / vitest 全绿（含新增用例）。
- 起服务实测：假模型工具循环触发 ask_user → `GET /questions` 待答；`POST answer` 后会话出现用户答复并产生 Agent 回合。

## 5. 边界（本轮不做）

- 不做超时自动取消/提醒；不做多问题一屏（同时只允许 1 个待答问题/会话）。
- `ask_user` 仅 user 会话可用（会议已有决策点机制，不重复）。
- 审批（command/submit）沿用现有 approval 流程，本轮只把"提问/确认"补齐并统一汇聚到「需你处理」。
