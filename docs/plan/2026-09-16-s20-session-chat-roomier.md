# S20 方案：会话页聊天区放大（高度自适应视口 + 左右两栏可收起）

> 日期：2026-09-16　类型：可用性改进（用户直接指令，多选确认取 1+2）　真源：`design/ui.md` §4（对话导航 3 栏）
> 关联：`docs/changes/2026-09-16-s20-session-chat-roomier.md`、`docs/plan/development.md`

## 1 需求

用户口径：**"会话的聊天窗口太小，看着不舒服"** —— 诊断后确认取两条改法：

| # | 需求 | 验收 |
| --- | --- | --- |
| R1 | **消息区高度自适应视口** | 消息区 `maxHeight: 420`（写死）→ `calc(100vh - 350px)`、`minHeight: 300`；1080p 屏上从约 420px 提到约 730px；窗口变矮时不低于 300px，不发生"压到 0" |
| R2 | **左栏（会话列表）可收起** | 收起后中间聊天区多出约 296px；收起态是一条窄竖条（竖排文字「会话列表 ›」），点击展开 |
| R3 | **右栏（任务/询问/审批）可收起** | 收起后中间聊天区再多约 356px；展开态右上角有「收起 ›」，收起态为窄竖条「‹ 任务·询问·审批」 |
| R4 | **收起状态被记住** | 写入 `localStorage`（key `agent-haness.session-panel-collapsed`），切标签页/刷新后保持；隐私模式或配额异常时静默降级为"本会话内有效" |
| R5 | 只动会话页布局 | 拓扑页、其它标签页布局不变；接口与后端零改动 |

## 2 现状与根因（实测约束）

会话页（对话导航）宽度是**硬编码叠加**出来的：

| 环节 | 占用 |
| --- | --- |
| 全局左侧主导航 `Sider` | 168px |
| `Content` padding | 24 × 2 = 48px |
| 两处 `gap: 16` | 32px |
| 左栏会话列表 | 固定 280px |
| 右栏三列表 | 固定 340px |
| **中间聊天区** | **视口宽 − 868** |

→ 1920 屏约 1050px（尚可），**1440 屏约 570px、1366 屏约 500px**（明显偏窄）。

高度问题独立存在且更明显：消息区写死 `maxHeight: 420`，1080p 屏上竖向可用空间约 950px，**白浪费约 500px**，看长日志必须不停滚。

## 3 关键决定

1. **先改高度，再改宽度**：高度是"零成本纯收益"（不牺牲任何信息），宽度收起是"用信息密度换空间"（隐藏后可见内容变少）——两件事都要，但语义不同，实现上互不耦合。
2. **收起用"窄竖条"而不是"完全隐藏"**：完全隐藏会让用户找不到回来的入口；窄竖条（约 30px）用竖排文字自解释（`writing-mode: vertical-rl`），不依赖图标库（项目未声明 `@ant-design/icons` 依赖，避免用传递依赖）。
3. **收起状态落 `localStorage`**：单机单用户、无账号体系，用浏览器本地记忆最省事；读写在 `try/catch` 里，任何异常（隐私模式/配额）只影响"记忆"不影响功能。
4. **不做右栏待办数的收起态提醒**：`RightColumn` 自己拉数据，收起后要显示 pending 角标就得把数据提升到父组件。本轮不做（记入遗留）——收起是用户主动选择，需要时点开即可。
5. **不改三栏宽度本身**（280/340 保持）：窄屏用户可以用收起得到空间；直接把宽度改小会让大屏用户信息变少。全局瘦身（主导航/padding）是另一条独立改法，本轮不做（用户未选）。

## 4 实现步骤

- `web/src/pages/SessionPanel.tsx`
  - 模块级：`COLLAPSE_KEY`、`readCollapsed()`/`writeCollapsed()`（`try/catch` + 结构校验，默认 `{left:false,right:false}`）。
  - 组件内：`const [collapsed, setCollapsed] = useState(readCollapsed)`、`toggleCollapsed(side)`（写入 localStorage）。
  - 消息区：`maxHeight: 'calc(100vh - 350px)'` + `minHeight: 300`（保留 `overflowY: 'auto'`）。
  - 左栏：展开态给 `Card` 加 `extra`「‹ 收起」；收起态渲染窄竖条按钮「会话列表 ›」（`Tooltip` 兜底解释）。
  - 右栏：展开态在原 `<div style={{width:340…}}>` 内、`RightColumn` 上方加右对齐「收起 ›」；收起态渲染窄竖条「‹ 任务·询问·审批」。
- 文档回写：`design/ui.md` §4（栏宽/高度/收起口径）；`README.md`/`plan/development.md`/`testing/plan.md` 索引与记录；验收阶段清单加 `s20`。

## 6 风险

| 风险 | 对策 |
| --- | --- |
| `calc(100vh - 350px)` 估算偏差导致页面轻微上下滚动 | 估算已含 header 64 / Content padding 48 / 标题栏 / Tabs / Card header / 输入框 / 状态行；偏差只表现为"少一点或略多一点"，不产生功能性错误 |
| 竖排文字在部分字体下换行难看 | 竖条只放 4~6 个字并配 `Tooltip`；窄条宽度给 28~32px |
| `localStorage` 不可用 | `try/catch` 包裹，失败即退化为默认展开 |
| 收起后忘记右栏有待答询问 | 中间卡片本身会显示询问卡（待答项在会话流里可见）；右栏收起只影响三个列表的常驻展示 |
