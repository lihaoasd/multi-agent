## 2. 重点覆盖的业务规则（每项含正常/边界/非法/异常）

1. 单工不变式：同一 Agent 不同时在两个活动会话；会议入会挂起 user 会话，散会恢复。
2. 会议轮次/决策点：阻塞后除用户答复外无推进；插话不打断生成但纳入议程；结束前未决议程提示。
3. 路径边界：越界读写一律拒绝并审计；符号链接逃逸拒绝。
4. 高危命令审批：未批准不执行；拒绝结果回注 Agent；批准/拒绝均有审计。
5. 提交制：文档提交写 workdir+manifest；版本递增与回退内容一致；delete action 需确认。
6. 会话日志：seq 单调、先盘后推、重启后 meta/log 重建状态一致。
7. 记忆：滚动摘要 ofSeq/toSeq 连续无重叠；L3 条目 active/superseded 规则；全局记忆写入权限（会议结论/决策才写）。
8. 中文检索：2-gram 命中与跳转（含标点/换行边界）。
9. 单实例与停用（D14-3/9）：同项目每模板至多 1 实例；停用后 dispatcher 不领活、user 会话只读归档、重新启用恢复同一会话。
10. 会话事件模型（H3/M3）：turn_start/turn_end 完整判定；轮转后 seq 跨文件单调、经 segments 跳转命中。
11. 回退内容一致性（H2）：doc 回退=versionDir 快照覆盖、code 回退=补丁反向应用，回退后 workdir 内容与快照一致。
12. 审批跨重启（M1）：pending 保持；决定落盘但不回放执行；Agent 恢复重试需重新审批。
13. 任务级代码聚合（D14-⑧/D15）：编辑归属 taskId；任务 done 后 artifact 文件清单=该任务全部变更；无任务按回合兜底；文件编辑锁命中返回 ERR_CONFLICT（M5）。
14. 会议并发与自主入会（D14-⑤/⑥）：单会议上限排队；成员"接受/稍后/拒绝"自主决定剧本（Mock）；散会后返回原工作并自主调整记录。
15. 原始时间线（D14-④）：会话事件按 kind 过滤完整可拉取；记忆列表 API 只读可用（M13）。
16. 会议状态与排队持久化（D16-①）：queued/proposed/open/blocked_waiting_user/closed 全状态落盘与重启重建；proposed 起占槽、queued 槽空自动转 proposed（重启后续接正确）。
17. plan-execute 回合语义（D16-③）：回合内用户消息只入队不打断；会议抢占→散会后同一会话续跑；跨重启缺 turn_end 不自动续跑（汇报中断点/续做剧本）。
18. 任务激活规则（D16-④，D17-① 修订）：每 Agent 单 in_progress（已有时新任务不可置位、无自动回退；仅完成或用户终止释放）；todo 不入上下文、口头指派改动按回合兜底；纪要转任务 creator=user。
19. 模板快照与 doc 审批预览（D16-⑤/⑥）：实例创建后修改/删除模板不影响既有实例（仅 UI 标「模板已移除」）；doc 提交审批卡含只读预览、审批记录带 previewRef。
20. 任务不抢占与终止（D17-①）：已有 in_progress 时新任务置位被拦（可先置 todo）；终止确认：存在未结算改动先结算为 code artifact 快照再置 `terminated`（可回退）；执行中终止到可中断点生效并回注 Agent（Mock 剧本验证后续步骤不再执行）。
21. 会议转台与通知分级（D17-②）：queued→proposed 静默、proposed→open 强通知、open→blocked 入「需你处理」待办条；成员决定聚合为阵容消息；queued/proposed 可取消、重启不残留排队项。
22. 「需你处理」待办条（D17-③）：阻塞级三类（会议拍板/高危命令审批/成员入会干预）的入条、原地操作、解除移除与源会话状态一致；doc 提交与任务完成确认不入条。
23. doc 审批降噪与信任（D17-④）：托盘批量同意/拒绝生效；信任开关默认仅 doc/test（config/deploy 仍逐条审批）；撤销后恢复逐条。
24. 未完成回合恢复（D17-⑤）：缺 turn_end 的会话重开/重连后标「未完成」点并展示横幅三选（汇报中断点/继续执行/忽略），三选行为与 plan 事件一致；文本半截消息补全按钮并存。
25. 可停止与进行中细条（D17-⑥）：流式「停止生成」停当前回合输出且队列保留；顶部「n 个 Agent 正在工作」列表项与 plan 事件一致（Mock 长任务剧本）。

## 3. 测试数据与隔离

- 每个测试用例使用独立临时项目目录（os.tmpdir 下创建，测后清理），绝不触碰真实 workdir。
- Mock 模型：可编程响应（按输入匹配/固定剧本），用于模拟会议"成员发言序列"与"模型失败重试"。
- 覆盖 flaky 点：流式中断、审批超时、文件并发写（单进程串行验证）。

## 4. 执行与门禁

- `npm run test`：单元+集成全绿是提交门槛。
- 每里程碑按 development.md 的"演示/验收"列人工验收；M8 跑 prd §9 完整脚本。
- 覆盖率目标：domain 与 infra 关键模块 ≥ 80%（配置跳过 UI 层）。
