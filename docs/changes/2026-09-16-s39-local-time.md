# 修改记录 · S39 时间显示改用本地时间（trace 时间差 8 小时）

> 类别：changes · 日期：2026-09-16 · 关联方案：[docs/plan/2026-09-16-s39-local-time.md](../plan/2026-09-16-s39-local-time.md)
> 关联设计：[ui.md](../design/ui.md) §4、[prd](../requirements/prd.md) FR-30 / D42

## 1. 需求 / 问题

用户口径：**"trace 的时间显示不对"**。

根因（两处同一个写法）：

| 位置 | 原实现 | 结果 |
| --- | --- | --- |
| `web/src/lib/event-display.ts` `shortTime()` | `ts.slice(11, 23)`（还有 `length < 23` 的格式猜测） | 事件 `ts` 是 `clock.now().toISOString()`（**UTC**），直接切片＝把 UTC 当本地时间显示。**本机 UTC+8，实测 `2026-09-17T11:52:29.007Z` 显示成 `11:52:29.007`，正确应为 `19:52:29.007`——差 8 小时** |
| `web/src/pages/RightColumn.tsx` 任务列表 | `task.updatedAt.slice(11, 19)` | 同一处伤（任务更新时间同样是 UTC） |

之所以一直没被发现：S35 的用例把 `11:52:29.007` 写成了期望值——**把 bug 钉成了契约**。

## 2. 改动范围

| 层 | 文件 | 说明 |
| --- | --- | --- |
| web | `web/src/lib/time-format.ts`（新） | 纯函数 `localClock(ts, {withMs})`：`new Date(ts)` → 本地 `getHours/getMinutes/getSeconds/getMilliseconds` + 补零；`withMs:false` 给 `HH:MM:SS`；缺失/空串 → `''`；不可解析 → **原样返回**（不伪造时间） |
| web | `web/src/lib/event-display.ts` | `shortTime(ts)` 改为**委托** `localClock(ts)`（签名不变，trace 调用方零改动），并补注释说明不再切 ISO 串 |
| web | `web/src/pages/RightColumn.tsx` | 任务列表时间改用 `localClock(task.updatedAt, { withMs: false })` |
| tests | `tests/unit/web/time-format.test.ts`（新 5）、`tests/unit/web/event-display.test.ts`（修正被钉成 UTC 的断言） | 见 §4 |
| docs | `prd`（**D42** + FR-30 补注）、`ui.md` §4、`README.md`、`plan/development.md`、`testing/plan.md`、验收阶段清单加 `s39` | 全链路回写 |

**未改**：事件落盘仍是 UTC ISO（`clock.now().toISOString()`）、接口与导出、日志格式；不引入日期库。

## 3. 关键决定

1. **显示本地时间**：单用户本机平台，用户对照的是自己的表；真要 UTC 会在界面标注时区（不在本轮）。
2. **一处真相**：界面钟点格式化只有 `localClock` 一份实现；`shortTime`（trace 用，带毫秒）与右栏任务时间（不带毫秒）都走它。
3. **不可解析就原样透出**：`new Date('不是时间')` → `NaN`，此时返回原串；缺失/空串返回 `''`——宁可露出原始值，也不给一个"看着对"的假时间。
4. **测试按不变量写，而不是按某个时区写**：断言"同一时刻的不同时区写法渲染成同一钟点"（`Z` 与 `+08:00`），这条与时区无关且能确定性地抓住旧实现（旧实现给 `11:52` 与 `19:52`）。

## 5. 遗留

- **不显示时区后缀**：显示的是本机本地时间，界面无 `+08:00` 之类标注；若将来要跨时区对照或统一 UTC，改 `localClock` 一处并在列头标注时区。
- **不带日期**：trace 与任务列表只给钟点（`HH:MM:SS[.mmm]`），一次会话通常在同一天内；跨天的历史事件需要日期时，加 `MM-DD` 前缀即可（同一纯函数内扩展）。
- **`export`/日志导出仍是 UTC ISO**（`sessionApi` 导出与 zip 导出）：属数据面而非显示面，本轮不动。
- 前端仍无 DOM/组件测试（同类提醒已在 S23/S27/S28/S29/S31/S32/S33/S34/S35/S36/S37/S38 记录）。
