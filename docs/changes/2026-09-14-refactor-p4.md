## 关键实现

### 1. 利用既有结构，而不是重新切分

`app.ts` 原本**已经**按域写成了 15 个 `function registerXxxRoutes(app, svc)`
——只是它们和组装代码在同一个文件里。因此拆分是"搬函数 + 补 imports"，
不需要解析源码结构（这正是 P3a 在 `service-tools.ts` 上失败的原因：
那个文件没有现成的分组边界）。

### 2. 修掉 6 条分层违规的正确姿势：补门面导出

拆分后 `routes.ts` 仍报 5 条"server 深入 application 内部模块"，
涉及 `fs-browse`（3 个纯函数）、`export`（1 个）、`meeting.withDisplay`、`question.QuestionService`。

**修法不是继续拆文件，也不是放宽规则**，而是在组合根 `composition.ts` 增加一段
"server 门面"导出（规则对 `composition.ts` 本就豁免，见其注释）：

```ts
export { browseDirectory, getHomeAndDrives, mkdirUnder } from './fs-browse/fs-browse-service.js'
export { collectProjectFiles } from './export/export-service.js'
export { withDisplay, type MeetingWithDisplay } from './meeting/meeting-service.js'
export type { QuestionRecord } from './question/question-service.js'
export async function questionAnswerText(rec: QuestionRecord): Promise<string>
```

判断依据是稳定且可复述的：**应用层内部模块之间照常互相 import；只有跨层访问必须走门面。**
server 从此只 import `../application/composition.js`——方向清晰，且由 eslint 机器校验。

### 3. `eslint.config.js` 重写（一次真实事故）

我在用 shell 做"删除一行常量"的正则替换时，**把该文件写成了非 UTF-8**（中文注释全部变成乱码，
ESLint 报 `SyntaxError`）。已用 `write` 工具按完整内容重写。

这已是本会话**第二次**因 shell 改写源文件导致编码损坏（P1a 的 `invite-store.ts` 是第一次）。
**结论升级为硬规则：本仓库任何源文件只用 `edit`/`write` 工具修改，不再用 shell 重定向/正则替换。**
（例外：纯 ASCII 的单行路径替换，且改后要验证编码与行尾。）

同时把 server 层从棘轮豁免中移除——**promote 为 error**：

```js
// promote 记录
// · src/server/**  → error（P4 路由拆分完成，2026-09-14）
```
