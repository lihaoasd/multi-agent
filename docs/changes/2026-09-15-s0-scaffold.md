## 2. 关键决定（可推翻）

1. **服务端 `tsx` 直跑、不产 `dist`**：`npm start` = `tsx src/bootstrap/main.ts`；`npm run build` = 服务端类型检查 + 前端构建。development.md 原列的 `tsconfig.build.json` 随之取消（避免两套运行口径）。**副作用**：部署文档需按此口径回写（已改）。
2. **版本以本机为准**：React 19.3 + antd 6.6 + Vite 8 + Vitest 5 + TS 6 + ESLint 10（设计文档原写 React 18 + antd 5）；仅新增 `@types/react`、`@types/react-dom` 两个类型包，无新增运行时依赖。
3. **容器释放语义修正**：首版 `dispose()` 在作用域容器上也会清空共享 singleton 释放队列，导致"作用域释放后再由根释放"丢失 singleton 的 dispose。改为 `isRoot` 判定 + 回归用例（`tests/unit/bootstrap/container.test.ts`）。
4. **Fastify notFound 单一注册**：首版 `registerErrorHandler` 与 `registerStaticRoutes` 都调用 `setNotFoundHandler`，启动即抛 `Not found handler already set`。改为错误处理器只管 `setErrorHandler`，404 分两种模式（纯 API → JSON；有前端 → SPA 回退），并补集成用例。
5. **ratchet 用 ESLint Node API**：受限环境下 `child_process` + piped stdio 会 EPERM，故门禁脚本不派生子进程。
6. **门禁先于业务代码**：`eslint.config.js` 的 zones 与 ratchet 基线在第一条业务代码之前生效（development.md §4 的核心目的）。
