## 2026-09-08 文档评审轮 3：交互设计评审问题闭环（D17-①~⑦ 定案）

- 需求/问题: 以交互设计师视角对全套文档（frontend/style.md 及 sessions/meetings/agent-runtime 等交互语义）评审两轮，识别核心缺口——"老板注意力编排"：需老板动作的事项分散于各会话、状态不可溯源、会议冻结与自动转台不可见、审批疲劳、长任务不可停止/中断无恢复入口等；经与用户逐条问答定案（六项决策 + 四项配套 UI 语义，全部采纳推荐方案，其中 D17-① 修订 D16-④）。
- 类型: 文档(变更/定稿)
- 决策（新增，见 prd §7 D17）:
  - D17-① 任务激活**不抢占**（修订 D16-④ 自动回退）：已有 `in_progress` 时新任务不可置位（可先 todo 排队、置位被拦并提示原因）；槽位仅由「任务完成（用户确认 done）」或「用户显式终止」释放，无静默状态变更。终止=带确认，有未结算改动先结算为一条 code artifact 快照再置 `terminated`（可回退）；执行中终止到可中断点生效并回注 Agent、停止后续计划步骤。
  - D17-② 会议转台通知分级：queued→proposed 静默可见不打扰；proposed→open 强通知（横幅）；open→blocked 最强打扰并入「需你处理」待办条；成员接受/拒绝/稍后聚合为一条阵容消息；queued/proposed 可取消（发起者或用户），重启不残留排队项。
  - D17-③ 「需你处理」最小版队列：MVP 顶部待办条仅聚合阻塞级三类（会议拍板＞高危命令审批＞成员入会干预），原地可操作+跳源会话；doc 提交与任务确认原位低打扰不入条；全量聚合 P1。
  - D17-④ doc 审批降噪：高危命令=强打断不可批量；doc 提交=静默托盘（角标计数、多选批量同意/拒绝、拒绝原因一次填写）；信任开关默认仅覆盖 doc/test，config/deploy 脚本类不放行，可撤销。
  - D17-⑤ 未完成回合恢复入口：缺 turn_end 会话打开项目/重连时标「未完成」点+横幅三选（汇报中断点/继续执行/忽略），非推送打扰，与文本补全按钮统一为恢复入口。
  - D17-⑥ 可停止与进行中可见性：流式「停止生成」按钮进 MVP；顶部细条「n 个 Agent 正在工作」进 MVP（Agent×任务×步骤，plan 事件驱动）；完整活动面板 P1。
  - D17-⑦ 配套 UI 语义：主持人征询期左栏「主持征询中」标签+user 会话挂起预告横幅；忙碌实例停用=待停用反馈（灰化角标/生效时点/可取消，waiting 先处理审批）；排队会议积压顺序/数量与取消；纪要待办转任务一步化（勾选即建，预填受派者与来源）。
