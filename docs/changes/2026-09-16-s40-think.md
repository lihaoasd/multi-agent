## 1. 需求 / 问题

用户口径：**"think 开启了吗，要开启 think，页面也要显示出来"**。

实测回答"有没有开"：**没开，而且是三处都断了**。本机 `data/` 的 10 个会话日志、198 条事件里 **`thought` = 0 条**（`plan` 16、`tool_call` 74）：

| # | 根因 |
| --- | --- |
| A | `strategies.ts` 只在 `direct` 首次调用与 `reflective` 的自查/修订调用上 `emitThought`；**`plan-execute`（内置模板默认策略）一条思考都不发**，`runToolLoop` 的多轮思考也全丢 → 页面永远看不到 |
| B | 四个适配器**请求侧从不带思考参数**，`capabilities.reasoning` 只是登记值、运行期无人消费 → Anthropic/Gemini/Ollama 永远不会思考 |
| C | **思考不回传**：[DeepSeek 文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)明确"带 `tools` 的请求，后续所有请求必须完整回传 `reasoning_content`，否则 400"；我们连 `reasoning` 都没放进 assistant 消息 |

旁证：同一项目的架构师会话有两次 `ERR_MODEL`（**60s 超时**），思考模式会显著变慢。

## 3. 关键决定

1. **能力标记驱动请求参数**：勾选＝用户确认该模型支持该协议参数；不勾选则**完全不发**（陌生参数会被部分厂商 400）。
2. **开关要用户可操作**：此前模型条目只能"看"能力标签、不能改（只有新增供应商表单有字段），本轮补上条目行开关与新增表单勾选。
3. **回传不受开关限制**：能力只管"要不要主动要求思考"；**拿到的思考一律回传**——DeepSeek 思考模式默认开，模型可能自己就思考了。
4. **Anthropic 带 tools 时不发 thinking**：其思考块（含 `signature`）在带工具调用的后续请求里必须原样回传，本平台尚未保存 signature；宁缺勿错，完整支持记遗留。
5. **思考按轮次独立落事件**：每条 `thought` 对应一次模型调用，便于与工具调用/回合对照。

## 5. 遗留

- **Anthropic 的思考与工具调用不能同轮**：需要保存 thinking block 的 `signature` 并随 assistant 消息回传才能真正带工具使用；本轮选择"带 tools 时不发 thinking"，避免 400。
- **思考内容不落"消息"、只落 `thought` 事件**：符合既有事件模型；若要参与后续上下文的拼接（DeepSeek 在带 tools 时会拼接 `reasoning_content`），需要把思考写进会话窗口的 messages——当前只在同一次工具循环内回传。
- **超时与思考的冲突（实测已发生）**：思考模式更慢，60s 的供应商超时曾让两个回合失败。建议在「模型 → 供应商」里把「超时（毫秒）」调大（如 180000）；本轮**不改默认值**（会影响其它供应商）。
- **思考条目很长时不能折叠**：会话流里 `thought` 是直接展示的纯文本；若觉得刷屏，可加"默认折叠、点击展开"（新交互，未做）。
- **`reasoningEffort` / `thinkingBudget` 只能写文件**：本轮 UI 只暴露「思考」开关，强度/预算仍走模型条目配置（`defaultParams`），UI 未暴露。
- 前端仍无 DOM/组件测试（同类提醒已在 S23/S27/S28/S29/S31/S32/S33/S34/S35/S36/S37/S38/S39 记录）。
