## 关键实现

### 1. 分层依赖规则（P0-2）

用 ESLint `no-restricted-imports` 实现 `architecture.md` §1「核心逻辑与 IO/框架解耦」与 §4 分层：

```
shared → （无内部依赖）
domain → shared
application → domain, shared, application/ports
infra → domain, shared, application/ports
server → application 门面（Services）, shared
```

`src/application/composition.ts` 是唯一豁免：组合根本职就是知道 infra 具体实现，但仍禁止依赖 `server`。

### 2. 棘轮（ratchet）而非一刀切

规则一旦写成 error，`npm run lint` 立刻红——违反"每阶段 lint 全绿"的阶段门禁。
因此采用棘轮：

- **存量 50 处违规**（分布在 20 个 application 模块 + `domain/rules/path-resolver.ts` + `server/app.ts`）→ 保持 `warn`
- **其余所有文件** → 同一条规则立即 `error`，新代码一律合规
- 每阶段完成时把对应豁免清单删掉，规则自动收紧为 error

**实测结果**：`npm run lint` = **0 error / 50 warning**（此前 0 error，规则引入了 54 条问题，其中 50 条为存量已降级）。

### 3. 特征化测试（P0-4）

搬迁前先把现有纯逻辑的行为固定为断言，任何搬迁引入的漂移都会失败：

- `deriveAgentState`：验证全序 `disabled > meeting > waiting > working > idle`，含"会议中压过 waiting""waiting 压过 working"两条历史踩坑规则
- `assessCommand`：22 条判定矩阵（deny / approval / allow）+ 程序名归一化（basename、去 `.exe/.cmd/.bat`、小写）

**只锁 `decision` + `ruleId`，不锁 `reason` 文案**——理由文案允许演进，判定结果不允许漂移。

## 过程中发现并如实锁定的两个现状问题（本次不修）

1. **`assessCommand` 离线判定对 `git push` 不可达**：`NET_OFFLINE` 检查位于 `GIT_PUSH` 等规则之后，
   因此 `git push` 即使 `offline=true` 也先命中 `GIT_PUSH`（approval）。
   特征化测试如实锁定该现状，并注明"是否调整属行为变更，另开方案"。
2. **`occupancy.activity` 的 `'waiting'` 不参与状态推导**：`deriveAgentState` 只识别 `meeting` / `working`；
   `waiting` 由待答提问/待批审批标志决定。测试锁定该现状。
