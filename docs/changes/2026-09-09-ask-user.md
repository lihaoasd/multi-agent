# 2026-09-09 角色向用户提问/确认/审批交互（单选·多选·确认·文本）

> 类别：changes · 需求来源：用户「角色需要用户询问，确认，审批交互，可以用户单选，多选等交互」
> 方案见 [docs/plan/2026-09-09-ask-user.md](../plan/2026-09-09-ask-user.md)

## 需求/问题

原有：高危命令/提交走**审批**（approvals.jsonl + 顶部待办），会议有**拍板**决策点。
缺失：Agent 在 user 会话里**主动向用户提问**（确认 / 单选 / 多选 / 自由文本）的结构化交互——
模型只能把问题写进正文，用户回答也只是普通聊天，没有可点选项、没有"待回答"状态。

## 交互设计（不阻塞进程、可恢复）

1. Agent 调 `ask_user{question, kind, options?, allowText?}` → 落一条 **pending 提问**；
   同一会话已有 pending 时再次提问被拒（防刷屏）。
2. 前端在会话输入框上方渲染**问题卡片**（confirm 确认/取消、single radio、multi checkbox、text 输入框 +
   可选补充说明）；「需你处理」弹窗内可**就地回答**，顶部角标同步计数。
3. 用户提交 → 记录 answered（严格校验选项）→ 答复作为一条**用户消息**写回会话 → **触发 Agent 回合**继续
   （复用既有唤醒机制，刷新/重启都不丢）。

## 改动范围

- 新增 `src/application/question/question-service.ts`：`ask/list/get/answer` + `answerText()`；
  存储 `questions.jsonl`（原子写）；校验：kind 合法、single/multi/confirm ≥2 选项、
  choice ∈ options、multi 非空且 ⊆ options、text 必填、已答不可重复、同会话仅 1 个 pending。
- `src/infra/tools/executor.ts`：`ToolEnv.sessionId?`（提问需绑定会话）。
- `src/application/tools/service-tools.ts`：注册 `ask_user`（availableIn:['user']，带 paramsSchema）；
  `registerServiceTools` 依赖增加 `questions`。
- `src/application/composition.ts`：新增 `QuestionService` 并挂到 `Services.questions`；注入 attention 与工具注册；
  `buildToolEnv(...,{sessionId})` 透传；`ask_user` 作为**平台交互能力**在 user 会话始终可用
  （老项目快照的 tools 白名单里没有也能用）。
- `src/application/attention/attention-service.ts`：待办新增 `kind:'question'`（带 questionId）。
- `src/server/app.ts`：`GET /api/projects/:pid/questions?status=&sessionId=`、
  `POST /api/projects/:pid/questions/:qid/answer`（回答后写回会话并触发回合；非 user 会话/角色停用只落记录并返回 wakeError）。
- `src/application/agent-loop/loop-runner.ts`：系统提示加入"需要用户拍板/确认/选择时用 ask_user，不要替用户决定"。
- 前端：`web/index.html` 新增 `#question-zone`；`web/app.js` 新增 `buildQuestionCard/renderQuestions/submitQuestionAnswer`
  与待办弹窗 question 分支；`web/style.css` 卡片样式。
- 审批（command/submit）沿用现有 approval 流程，本轮不改，仅与提问统一汇聚到「需你处理」。

## 验证

- `npx tsc -p tsconfig.json`、`npx eslint .` 通过；`npx vitest run --pool=threads` **131 用例全绿**
  （新增 `tests/question-m8h.test.ts` 3 例：kind/选项/重复回答/并发提问校验；
  工具调用→pending→待办计入→非法选项被拒→回答写回会话并触发新回合；多选答复格式）。
- 真实模型冒烟（deepseek-v4-flash）：模型**真实调用 `ask_user`** 发起单选提问
  （`kind=single`，给出 Canvas 2D / DOM 两个选项，allowText=true）→ 待办出现 `question` 项 →
  用户选「Canvas 2D」→ 状态 answered、wakeError=null → 会话出现用户答复
  `【回答提问 q_…】… → Canvas 2D…` → Agent 开新回合确认决定并继续追问下一项。

## 遗留（说明）

- 不做超时自动取消/提醒；同一会话同时只允许 1 个 pending 提问。
- `ask_user` 仅 user 会话可用（会议已有决策点机制，不重复）。
- 审批通过后不自动续跑 Agent 回合（既有边界）；提问的"回答→唤醒"已做闭环。
- 前端无浏览器 e2e：交互以「服务/API 单测 + 真实模型链路 + 静态资源校验」验证。
