# 修改记录 · S35 会话窗口加「详细日志（trace）」视图

> 类别：changes · 日期：2026-09-16 · 关联方案：[docs/plan/2026-09-16-s35-trace-view.md](../plan/2026-09-16-s35-trace-view.md)
> 关联设计：[ui.md](../design/ui.md) §4、[prd](../requirements/prd.md) FR-30 / D38

## 1. 需求 / 问题

用户口径：**"会话窗口，加一个 trace 日志查看，切换窗口详细日志"**。

现状：会话窗口只有"对话"视图（S22 把事件筛成五类），`plan` / `turn_start` / `turn_end` / `state` / `summary` / `artifact` / `approval_*` 这些**在界面上完全看不到**；而 `GET /sessions/:sid` 本来就返回全部事件——数据现成，缺的是渲染与切换入口。

## 3. 关键决定

1. **两个视图，而不是把 kind 筛选请回来**：S22 已按用户口径删掉筛选下拉；现在要"看完整日志"，正确形态是**换窗口**（`对话` / `详细日志`）。
2. **详细日志覆盖全部 kind、摘要可读**：`traceLine` 为每类事件写摘要（`plan` 带状态/步数/当前步、`turn_start` 带 loop 与计划步数、`state` 给 JSON、工具结果标成功/失败…），而不是一律 `JSON.stringify`。
3. **原始 payload 用开关（默认关）**：默认只给摘要（可读性优先），排查时打开开关看完整 JSON —— 避免 200 行 JSON 把窗口淹没。
4. **纯函数先行**：`traceLine` 可被 node 侧单测覆盖（延续 S23/S26/S28/S30/S33），界面只做映射。
5. **复用 S34 的滚动跟随**：把 `viewMode`/`showRawPayload` 加进 effect 依赖，切视图/展开 payload 后仍贴底。
6. **不动后端**：事件本来就在，本轮只新增一个"观察窗口"。

## 5. 遗留

- 详细日志**不做 kind 筛选/搜索**：一次最多 200 条（`sessionApi.detail(..., 200)`），靠"展开 payload"排查足够；若日志量再涨，可考虑虚拟滚动或首屏条数可调（当前 `limit` 是固定 200）。
- 详细日志**不自动拉更早的历史**（只有首屏 200 条 + WS 增量）：需要完整历史时可用 `GET /sessions/:sid/log?fromSeq=` 或导出 zip；若要"向下翻页加载更早事件"，属新增功能。
- payload JSON 直接 `JSON.stringify`（无折叠/高亮）：够用；要"可折叠 JSON 树"需要引入组件（会新增依赖，需先确认）。
- 前端仍无 DOM/组件测试（同类提醒已在 S23/S27/S28/S29/S31/S32/S33/S34 记录）。
