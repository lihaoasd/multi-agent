# 需求文档（PRD）· Agent Haness v0.2

> 类别：requirements · 状态：草稿(待评审) · 日期：2026-09-08
> 关联：术语表见 [docs/README.md](../README.md)；架构见 [architecture.md](../design/architecture.md)

## 1. 背景与目标

用户（个人开发者/小团队老板）希望在**本机**用一个由多个 AI 角色组成的虚拟研发团队完成软件开发。
平台是**场景引擎**的软件研发首场景：角色可抽象、可扩展，未来支持用户自行编辑角色与团队，套用到任意场景。

目标：用户以"老板"身份创建软件项目 → 组队（角色实例）→ 通过 1:1 会话驱动团队 → 产出物（文档/代码）落在选定工作目录 → 用户审批关键节点 → 得到可运行、可部署的软件。

## 2. 目标用户与使用形态

- 目标用户：懂软件开发的个人/小团队（本项目首个使用者即用户本人）。
- 形态：本地部署 Web 应用（Node.js 服务 + 浏览器访问 http://127.0.0.1:PORT），单机运行，不做多租户与账号体系（本机即用户）。

## 3. 核心角色设定

| 参与者 | 说明 |
| --- | --- |
| 用户(老板) | 决策者：提需求、决策、审批、指派；不是 Agent。 |
| PM Agent | 独立角色：协调进度、对齐需求与目标、把模糊目标推进为可执行安排；**可按编排图向下游委派任务**（见 D15/D19）。 |
| 产品经理 Agent | 需求澄清、编写 PRD、维护需求范围。 |
| 系统架构师 Agent | 技术方案、模块/接口/数据设计，评估可行性。 |
| 交互设计师 Agent | 流程、信息架构、交互说明。 |
| UI 设计师 Agent | 视觉方案、设计稿/规范。 |
| 高级开发 Agent | 编码实现、自测、重构。 |
| 测试工程师 Agent | 测试计划/用例、执行与缺陷报告。 |
| 运维工程师 Agent | 构建部署、环境脚本、监控与发布说明。 |

- 以上为**内置模板**；所有角色可**抽象增删**：系统级角色库维护模板；项目级实例化组队。
- 暂不确定是否每项目必须全角色——由用户创建项目时自主选择，不做强制。

## 4. 用户故事（US）

- **US-1 创建项目**：作为老板，我创建项目时输入名称、描述并**选择工作目录**（支持空目录/已有代码仓库），系统生成团队与初始会话，让我立刻能对话。
- **US-2 一对一指挥**：我打开某 Agent 的会话窗口直接聊天：提问、下达任务、追问、修正；Agent 答复（可含思考过程与工具动作）。
- **US-3 委派与执行**：我把任务委派给某 Agent（经 UI 创建/指派，D15：MVP 默认由用户驱动）；Agent 在**项目工作目录**内工作（读代码/写文件/跑命令/自测，目录内容对所有角色可读），关键结果汇报到会话，产出按提交制登记进入工作目录。
- **US-4 进度可视**：我能看到每个 Agent 的状态（空闲/工作中/等待中）与当前所在会话。
- **US-7 切换与恢复**：任意时刻我关闭浏览器/重启机器，重开后能继续任意会话，Agent 依据 session log 与记忆恢复上下文。
- **US-8 历史检索**：我能在项目内按关键词检索历史会话与记忆。
- **US-9 已有代码库**：我指向一个已有仓库作为工作目录，团队先读代码/结构再谈需求与改动。
- **US-10 自定义角色**：我在系统角色库新建角色模板：名称、职责、系统提示词、agent loop、模型；随后可在任意项目使用。
- **US-11 自定义团队**：创建项目时我从角色库勾选成员（默认全勾 8 个内置模板，D14-1）、可改名/调提示词/换模型/换 loop；项目进行中也可增删成员（MVP 删除=停用保留数据，可重新启用，见 D14-9）。
- **US-12 产出物管理**：Agent 提交的产出物（文档/代码/测试/部署包）在工作目录可见；我能在界面查看提交记录（署名/版本/摘要）并回退。
- **US-13 审批**：高危命令与（按策略）关键提交需我批准后才执行/入目录。
- **US-14 多项目**：我能在项目列表页新建/打开/删除多个项目（当前 MVP 顺序处理互不干扰）。
- **US-15 工具包浏览**：我在首页工具模块看到工具包列表，能展开看每个包里有哪些工具、用途与风险；MVP 不能自制工具包（后续开放）。
- **US-16 Agent 库浏览**：我在首页 Agent 模块看到 Agent 模板列表，逐个可见 **loop / 提示词 / 工具 / 模型**（以及场景标签与审批规则）；MVP 不能提交配置（后续开放）。
- **US-17 编排画布**：在项目页拓扑导航里，我看到每个 Agent 的卡片与它们之间的有向连线；我能增删 Agent、连线、编辑布局并保存，从图上观测整体工作情况。
- **US-18 会话与工作日志**：在项目页对话导航里，我用左栏切换各个角色的会话，中栏看消息与 Agent 的工作日志，右栏看任务/询问/审批。
- **US-19 对话即启动与自动委派**：我在某个 Agent 的会话里对话，就等于让该 Agent 开始工作；它会按编排图沿出边创建并委派任务，受派 Agent 领取后独立执行。
- **US-20 询问答复**：Agent 需要我决策时向我提问，我在右栏询问列表里答复，它继续干活。
- **US-21 暂停与停止**：我可以暂停某个 Agent（不再领新任务）或停止它当前的任务。

> 编号空缺（US-5/US-6）表示该需求已随"会议功能移除"（2026-09-14）删除；编号不复用。

## 5. 功能需求（FR，MoSCoW）

### P0（MVP 必须）

- FR-01 项目管理：列表、创建（名称/描述/选择工作目录/勾选角色）、打开、删除（仅删运行时数据，提示不影响工作目录）。
- FR-02 角色抽象与实例化：角色模板库（内置 8 个软件团队模板 + 用户自建，带**场景标签**）；**首页 Agent 模块只读展示**模板的 loop/提示词/工具/模型（配置提交后续，见 FR-27）；项目内实例可改名/改提示词/换模型/换 loop；Agent 状态可见。
- FR-03 用户↔Agent 1:1 会话：消息收发（流式）、会话历史加载、并发约束(单工)下的排队与提示。
- FR-04 Agent 单轮执行：按所选 agent loop 执行一次回复；思考/工具调用/结果以事件流推给前端并**全量落日志**。
- FR-05 消息与会话日志：每会话结构化全量日志(JSONL)；会话列表/历史/恢复加载。
- FR-06 共享工作目录与文件归属（2026-09-14 修订：取消私有工作区）：所有角色的产出都在**项目工作目录**内进行；目录内容**全员可读**（角色间共享）；每个文件按 `file-owners` 归属创建者，**只有归属者可修改**，他人只能另建新文件（用户本人不受归属校验）。
- FR-07 产出物提交制：Agent 将产出整理为 Artifact 提交(署名/类型/文件清单/摘要/版本)；落地工作目录并写 manifest；可回退。
- FR-08 任务轻量管理：任务含标题/受派者/创建者/状态/关联会话/产出物，右栏任务列表可见；**Agent 委派为默认**（D19-④/⑤）：Agent 只能沿编排图**出边**创建/委派任务，受派者**领取**后执行；用户仍可手动派单、改状态、终止与干预，**不受边约束**。
- FR-10 模型接入与路由：OpenAI 兼容 API / Ollama / Mock 三后端；按角色/loop 步骤可配置不同模型。
- FR-11 记忆（双层+全文）：会话全量日志、滚动摘要、角色长期记忆、项目全局记忆；关键词检索（先全文+简单索引，向量留扩展点）。
- FR-12 UI：全局导航（项目 / Agent / 工具）；项目页双导航——**拓扑页 2 栏**（左编排画布 + 右任务/询问/审批）与**对话页 3 栏**（左会话切换 + 中会话流含工作日志 + 右三列表）；询问卡与审批卡；流式打字效果（详见 FR-25/28/29/30 与 [design/ui.md](../design/ui.md)）。
- FR-13 工具执行与安全：文件读写限定在**项目工作目录**内（+只读平台资源）；他人产出物只读；命令执行限制在项目工作目录内；高危动作（删除/覆盖大范围/安装依赖/改配置/git 变基等）走用户审批；全程记录审计轨迹。
- FR-14 单工调度：Agent 同一时刻只有一个活动会话；其余消息排队，到可中断点后处理。
- FR-25 首页与全局导航：工具 / Agent / 项目三模块；进入默认落在项目模块；三模块均可浏览（MVP 只读，见 FR-26/FR-27）。
- FR-26 工具包展示：工具按**包**组织展示（MVP 7 个基础包：`fs`/`cmd`/`memory`/`session`/`artifact`/`approval`/`task`，**全员必选**）；可见包内工具、用途与风险；**自定义工具包制作后续**（U8）。
- FR-27 Agent 库展示：模板列表与详情，含 **loop / 系统提示词（只读预览）/ 工具（按包分组）/ 模型 / 审批规则 / 场景标签**；MVP 只读，**配置提交后续**（U9）。
- FR-28 项目编排画布：节点 = Agent 实例卡片，有向边 = "可创建/委派任务"的关系；支持增删节点、连线、移动、**保存**（校验：无自环、无重复边、节点属本项目、`version` 乐观并发）；节点显示**状态徽标与当前任务**，用于观测总体工作情况。
- FR-29 项目页布局：**拓扑页 2 栏**（左画布 + 右三列表）、**对话页 3 栏**（左会话切换 + 中会话流 + 右三列表）；右栏三列表（任务/询问/审批）两页共用。
- FR-30 会话工作日志：会话流内联展示 Agent 的 `thought`/`tool_call`/`tool_result`/`plan`/回合边界事件（默认折叠、可展开），支持"仅对话 / 全部事件"切换与按 kind 过滤。
- FR-31 对话即启动与自动委派：用户在 Agent 会话中发消息即让该 Agent 开工；**各 Agent 独立工作**，不设项目级运行状态；Agent 按**出边**委派任务，受派者领取执行，完成/受阻**沿同一条边反向汇报**；越权委派被拒（`ERR_ORCHESTRATION_EDGE`）。
- FR-32 询问与答复：Agent 可向用户提问（问题 + 选项）并**阻塞等待**（Agent 状态 `waiting`）；右栏询问列表可原地答复，答复后 Agent 继续；每 Agent 同一时刻至多 1 个待答询问。
- FR-33 暂停与停止：Agent 级控制——**暂停**=不再领新任务、当前回合到可中断点挂起；**停止**=终止当前任务（存在未结算改动时先结算为 code artifact 快照）；均需确认并留审计。

### P1（MVP 后一期）

- FR-15 全文检索体验增强（高亮/时间线跳转）。
- FR-16 产出物 diff 预览与版本对比（文本/文档）。
- FR-17 已有代码仓库增强：导入结构摘要、改动影响分析、按文件归属任务。
- FR-18 会话「打断/继续」显式控制；agent 排队队列可视化。
- FR-19 记忆条目的用户可编辑/删除/钉住。

### P2（远期/场景化）

- FR-21 任意场景模板：把"角色库+团队编排+产出物类型+loop"打包为场景模板。
- FR-22 向量语义检索记忆。
- FR-23 Agent 间 1:1 直连会话（MVP 不提供，协作以产出物与全局记忆为媒介，避免上下文失控）。
- FR-24 多项目并发运行/任务并行度调节；云端部署与账号。

## 6. 非功能需求

| 项 | 要求 |
| --- | --- |
| 运行环境 | 本机 Windows(Win10/11)/macOS/Linux；Node.js ≥ 20；浏览器 Chrome/Edge。 |
| 存储 | **纯文件系统**（JSON/JSONL/Markdown），不用 SQLite/外部 DB；拷贝运行时项目文件夹即可迁移。 |
| 实时性 | 消息、Agent 状态、任务/询问/审批、编排图变更均走 WS 推送；回复流式输出（WS chunk），首字延迟目标 < 2s。 |
| 安全边界 | 所有 Agent 文件/命令活动被限制在：该项目工作目录(+只读平台内置模板)；写入另受**文件归属**约束（只能改自己名下或无归属的文件，他人产出物只读）；高危需审批；日志审计。 |
| 可恢复性 | 服务/浏览器随时可重启；会话状态落盘可重建；不丢已落日志。 |
| 可扩展性 | 角色模板/loop/模型 Provider/工具集/产出物类型/前端面板均有稳定扩展点。 |
| 易用性 | 全程中文 UI；一个从未配置过 Key 的用户用 Mock 模型即可跑通全流程。 |

## 7. 已确认决策记录（2026-09-08 问答归档）

| # | 议题 | 决策 |
| --- | --- | --- |
| D1 | 是否需要独立 PM | **设独立 PM Agent**；负责拆解/协调/对齐需求与目标；用户是老板做最终决策；角色可增删。（MVP 默认口径按 D15 收敛：不直接创建任务，仅协调与对齐） |
| D3 | 工作空间与产出物衔接 | **提交制（2026-09-14 修订：取消私有工作区）**：所有角色直接在同一**项目工作目录**内产出（草稿与成品都在这里），文件**全员可读、仅归属者可改**；产出以 artifact 登记（署名/版本/文件清单），可回退。 |
| D4 | 内置 agentloop 含义 | 思考/执行循环**模板**（单轮直答/反思/计划-执行…），创建角色时选择；**模型可替换**，不同角色可用不同模型。 |
| D5 | 技术栈 | **Node.js + TypeScript**；**不使用 SQLite**。 |
| D6 | 数据存储 | **纯文件系统**：项目=运行时文件夹(配置+日志+记忆)+用户选定工作目录(产出物)；JSON/JSONL/Markdown；拷贝即迁移；全文用自建简单索引；向量检索留扩展点。 |
| D7 | 记忆能力 | 全文/结构化+摘要**双层**；关键词检索 MVP 可用；向量检索后续。 |
| D8 | 工作目录类型 | 同时支持**空目录**与**已有代码仓库**（团队先读代码）。MVP 重点空目录，保留读已有代码能力。 |
| D9 | 旧文档 | README 中 v1 构想（固定 7 角色/顺序流水线/审批）**整体弃用重写**，不保留对照。 |
| D10 | 前端框架 | React + Vite。 |
| D11 | Agent 并发 | **单工**：同一时刻一个 Agent 只在一个会话活动。 |
| D12 | 命令执行安全 | **目录受限 + 高危审批**：活动限于项目工作目录（+只读平台资源）；高危命令需用户批准。 |
| D13 | 代码产出路径与审批默认值（2026-09-08 补充确认） | ① 代码走**工作目录内受控编辑**（每次变更留 diff 审计）+ **任务级批量生成提交记录**（署名/版本/可回退）；纯文档/草稿与代码同路径——直接在项目工作目录内定稿（署名、归属），再按类型登记 artifact。② 审批默认：**文档类提交需审批、代码类提交无需审批（留痕即可）、高危命令需审批**；均可配置为更强策略。"阶段基线锁定"按 P1 预留，MVP 不做。 |

## 8. 边界与不做事项（MVP）

- 不做账号/权限体系、不做远程/云端部署、不做多用户实时协同编辑。
- 不做 Agent 间 1:1 私聊，也不做多方会话（跨角色协作以任务委派 + 产出物 + 全局记忆为媒介）。
- 不做代码自动执行到生产环境的持续部署（运维产出部署脚本与手册，由用户执行）。
- 不做 SQLite/外部数据库；不做消息加密。
- 不做多语言 UI（中文优先，后续可扩展 i18n）。
- 不在工作目录自动 git 操作（除非用户授权的高危审批）；不隐式安装第三方运行时（如 Docker）。

## 9. MVP 成功标准与验收方式

1. **可跑通全流程（验收主路径）**：本机 `npm run dev` 起服务 → 首页看到工具包（7 个基础包）与 Agent 模板（含场景标签）→ 创建项目（选空目录；角色默认全勾 8 个内置模板）→ 进入项目页拓扑导航，画布连线（如 `pm → dev`、`dev → qa`）并保存 → 切到对话导航，在 PM 会话发消息（＝启动）→ PM 沿出边委派任务 → dev 领取开工 → dev 需要我决策时提问、我在右栏询问列表答复 → dev 汇报完成 → 我在右栏任务列表确认 → 产出物与记忆可见 → 关闭浏览器重开仍能恢复会话与画布。验收人：用户本人按上述脚本走通。
2. **Mock 模型全流程可用**：无任何 API Key 也可演示完整闭环。
3. **单工与状态正确**：同一 Agent 不会同时出现在两个活动会话中处理；状态面板与实际一致。
4. **安全**：高危命令无审批不可执行；Agent 无法读写项目工作目录之外的文件；他人产出物不可修改（`ERR_FORBIDDEN`）。
5. **文档交付**：全套文档评审通过；编码阶段按 docs/plan/development.md 执行。
6. **编排约束生效**：Agent 向非出边节点委派任务被拒绝（`ERR_ORCHESTRATION_EDGE`），画布不产生新边；用户手动派单不受此限制。
7. **控制与询问可用**：暂停后该 Agent 不再领取新任务且当前回合到可中断点挂起；停止后当前任务终止（未结算改动已先结算为 snapshot）；询问与审批均可在右栏原地处理，处理完 Agent 继续。
