# 需求文档（PRD）· Agent Haness v0.2

> 类别：requirements · 状态：草稿(待评审) · 日期：2026-09-08
> 关联：术语表见 [docs/README.md](../README.md)；架构见 [architecture.md](../design/architecture.md)

## 1. 背景与目标

用户（个人开发者/小团队老板）希望在**本机**用一个由多个 AI 角色组成的虚拟研发团队完成软件开发。
平台是**场景引擎**的软件研发首场景：角色可抽象、可扩展，未来支持用户自行编辑角色与团队，套用到任意场景。

目标：用户以"老板"身份创建软件项目 → 组队（角色实例）→ 通过会话与会议驱动团队 → 产出物（文档/代码）落在选定工作目录 → 用户审批关键节点 → 得到可运行、可部署的软件。

## 2. 目标用户与使用形态

- 目标用户：懂软件开发的个人/小团队（本项目首个使用者即用户本人）。
- 形态：本地部署 Web 应用（Node.js 服务 + 浏览器访问 http://127.0.0.1:PORT），单机运行，不做多租户与账号体系（本机即用户）。

## 3. 核心角色设定

| 参与者 | 说明 |
| --- | --- |
| 用户(老板) | 决策者：提需求、拍板、审批、插话、指派；不是 Agent。 |
| PM Agent | 独立角色：协调进度、主持/组织会议、对齐需求与目标、把模糊目标推进为可执行安排（MVP 默认不直接创建/指派任务，见 D15）。 |
| 产品经理 Agent | 需求澄清、编写 PRD、维护需求范围。 |
| 系统架构师 Agent | 技术方案、模块/接口/数据设计，评估可行性。 |
| 交互设计师 Agent | 流程、信息架构、交互说明。 |
| UI 设计师 Agent | 视觉方案、设计稿/规范。 |
| 高级开发 Agent | 编码实现、自测、重构。 |
| 测试工程师 Agent | 测试计划/用例、执行与缺陷报告。 |
| 运维工程师 Agent | 构建部署、环境脚本、监控与发布说明。 |

- 以上为**内置模板**；所有角色可**抽象增删**：系统级角色库维护模板；项目级实例化组队。
- 暂不确定是否每项目必须全角色——由用户创建项目时自主选择，不做强制。

## 4. 用户故事（US）

- **US-1 创建项目**：作为老板，我创建项目时输入名称、描述并**选择工作目录**（支持空目录/已有代码仓库），系统生成团队与初始会话，让我立刻能对话。
- **US-2 一对一指挥**：我打开某 Agent 的会话窗口直接聊天：提问、下达任务、追问、修正；Agent 答复（可含思考过程与工具动作）。
- **US-3 委派与执行**：我把任务委派给某 Agent（经 UI 创建/指派，D15：MVP 默认由用户驱动）；Agent 在私有工作区工作（读代码/写草稿/跑命令/自测），关键结果汇报到会话，产出按提交制进入工作目录。
- **US-4 进度可视**：我能看到每个 Agent 的状态（空闲/工作中/会议中/等待中）与当前所在会话。
- **US-5 发起会议**：某 Agent（如 PM）发起多人会议，主题/议程可见；会议中只沟通不干活；我在其中，可插话；**需我拍板时会议阻塞等待**，我答复后继续。
- **US-6 会议纪要**：会议结束自动产出摘要，写入各参与 Agent 的记忆与项目全局记忆，我随时可回看。
- **US-7 切换与恢复**：任意时刻我关闭浏览器/重启机器，重开后能继续任意会话，Agent 依据 session log 与记忆恢复上下文。
- **US-8 历史检索**：我能在项目内按关键词检索历史会话与记忆。
- **US-9 已有代码库**：我指向一个已有仓库作为工作目录，团队先读代码/结构再谈需求与改动。
- **US-10 自定义角色**：我在系统角色库新建角色模板：名称、职责、系统提示词、agent loop、模型；随后可在任意项目使用。
- **US-11 自定义团队**：创建项目时我从角色库勾选成员（默认全勾 8 个内置模板，D14-1）、可改名/调提示词/换模型/换 loop；项目进行中也可增删成员（MVP 删除=停用保留数据，可重新启用，见 D14-9）。
- **US-12 产出物管理**：Agent 提交的产出物（文档/代码/测试/部署包）在工作目录可见；我能在界面查看提交记录（署名/版本/摘要）并回退。
- **US-13 审批**：高危命令与（按策略）关键提交需我批准后才执行/入目录。
- **US-14 多项目**：我能在项目列表页新建/打开/删除多个项目（当前 MVP 顺序处理互不干扰）。

## 5. 功能需求（FR，MoSCoW）

### P0（MVP 必须）

- FR-01 项目管理：列表、创建（名称/描述/选择工作目录/勾选角色）、打开、删除（仅删运行时数据，提示不影响工作目录）。
- FR-02 角色抽象与实例化：角色模板库（内置 8 个模板 + 用户自建）；项目内实例可改名/改提示词/换模型/换 loop；Agent 状态可见。
- FR-03 用户↔Agent 1:1 会话：消息收发（流式）、会话历史加载、并发约束(单工)下的排队与提示。
- FR-04 Agent 单轮执行：按所选 agent loop 执行一次回复；思考/工具调用/结果以事件流推给前端并**全量落日志**。
- FR-05 消息与会话日志：每会话结构化全量日志(JSONL)；会话列表/历史/恢复加载。
- FR-06 私有工作区：每个 Agent 一个隔离目录，可读写；Agent 间不可见。
- FR-07 产出物提交制：Agent 将产出整理为 Artifact 提交(署名/类型/文件清单/摘要/版本)；落地工作目录并写 manifest；可回退。
- FR-08 任务轻量管理：委派任务(标题/受派者/状态/关联会话/产出物)，列表可见；**MVP 默认状态流转由用户经 UI 驱动**（新建/改状态），Agent 在会话中汇报完成（D15）；可选开启 Agent 工具通道（task_* 已实现、默认关闭，见 D15/D14）用于效果对比。
- FR-09 会议：任一 Agent 可发起(自动成为主持人)；指定成员(≥1 Agent)与主题/议程；用户恒在会；会内只沟通不干活；异步轮次推进；需用户决策点阻塞等待；用户插话；主持人或用户可结束会议；自动总结回写记忆。
- FR-10 模型接入与路由：OpenAI 兼容 API / Ollama / Mock 三后端；按角色/loop 步骤可配置不同模型。
- FR-11 记忆（双层+全文）：会话全量日志、滚动摘要、角色长期记忆、项目全局记忆；会议摘要回写；关键词检索（先全文+简单索引，向量留扩展点）。
- FR-12 UI：创建项目页、项目列表页、**三栏工作台**(左 Agent 列表+状态 / 中会话窗口 / 右会话列表+产出物+任务面板)；审批弹窗；流式打字效果。
- FR-13 工具执行与安全：文件读写在私有区/工作目录受限执行；命令执行限制在项目工作目录内；高危动作（删除/覆盖大范围/安装依赖/改配置/git 变基等）走用户审批；全程记录审计轨迹。
- FR-14 单工调度：Agent 同一时刻只有一个活动会话；会议入会挂起个人会话，散会恢复。

### P1（MVP 后一期）

- FR-15 全文检索体验增强（高亮/时间线跳转）。
- FR-16 产出物 diff 预览与版本对比（文本/文档）。
- FR-17 已有代码仓库增强：导入结构摘要、改动影响分析、按文件归属任务。
- FR-18 会话「打断/继续」显式控制；agent 排队队列可视化。
- FR-19 记忆条目的用户可编辑/删除/钉住。
- FR-20 会议模板（例会/评审会/复盘会）与议程模板。

### P2（远期/场景化）

- FR-21 任意场景模板：把"角色库+团队编排+产出物类型+loop"打包为场景模板。
- FR-22 向量语义检索记忆。
- FR-23 Agent 间 1:1 直连会话（当前统一走会议，避免上下文失控）。
- FR-24 多项目并发运行/任务并行度调节；云端部署与账号。

## 6. 非功能需求

| 项 | 要求 |
| --- | --- |
| 运行环境 | 本机 Windows(Win10/11)/macOS/Linux；Node.js ≥ 20；浏览器 Chrome/Edge。 |
| 存储 | **纯文件系统**（JSON/JSONL/Markdown），不用 SQLite/外部 DB；拷贝运行时项目文件夹即可迁移。 |
| 实时性 | 消息走 WS 推送；回复流式输出（SSE/WS chunk），首字延迟目标 < 2s。 |
| 安全边界 | 所有 Agent 文件/命令活动被限制在：该 Agent 私有工作区 + 该项目工作目录(+只读平台内置模板)；高危需审批；日志审计。 |
| 可恢复性 | 服务/浏览器随时可重启；会话状态落盘可重建；不丢已落日志。 |
| 可扩展性 | 角色模板/loop/模型 Provider/工具集/产出物类型/前端面板均有稳定扩展点。 |
| 易用性 | 全程中文 UI；一个从未配置过 Key 的用户用 Mock 模型即可跑通全流程。 |

## 7. 已确认决策记录（2026-09-08 问答归档）

| # | 议题 | 决策 |
| --- | --- | --- |
| D1 | 是否需要独立 PM | **设独立 PM Agent**；负责拆解/协调/组织会议；用户是老板做最终决策；角色可增删。（MVP 默认口径按 D15 收敛：不直接创建任务，仅协调/组织会议） |
| D2 | 会议推进与用户在场 | **异步推进**；讨论中需要用户决策的点**阻塞等待**用户回复后继续；用户可随时**插话**；用户恒为会议成员。 |
| D3 | 工作空间与产出物衔接 | **提交制**：角色先在私有工作区产出草稿/中间物，显式"提交"才进入共享产出目录（=工作目录），带署名/版本，可回退。 |
| D4 | 内置 agentloop 含义 | 思考/执行循环**模板**（单轮直答/反思/计划-执行…），创建角色时选择；**模型可替换**，不同角色可用不同模型。 |
| D5 | 技术栈 | **Node.js + TypeScript**；**不使用 SQLite**。 |
| D6 | 数据存储 | **纯文件系统**：项目=运行时文件夹(配置+日志+记忆)+用户选定工作目录(产出物)；JSON/JSONL/Markdown；拷贝即迁移；全文用自建简单索引；向量检索留扩展点。 |
| D7 | 记忆能力 | 全文/结构化+摘要**双层**；关键词检索 MVP 可用；向量检索后续。 |
| D8 | 工作目录类型 | 同时支持**空目录**与**已有代码仓库**（团队先读代码）。MVP 重点空目录，保留读已有代码能力。 |
| D9 | 旧文档 | README 中 v1 构想（固定 7 角色/顺序流水线/审批）**整体弃用重写**，不保留对照。 |
| D10 | 前端框架 | React + Vite。 |
| D11 | Agent 并发 | **单工**：同一时刻一个 Agent 只在一个会话活动；进会议挂起个人会话。 |
| D12 | 命令执行安全 | **目录受限 + 高危审批**：活动限于工作目录与私有区；高危命令需用户批准。 |
| D13 | 代码产出路径与审批默认值（2026-09-08 补充确认） | ① 代码走**工作目录内受控编辑**（每次变更留 diff 审计）+ **任务级批量生成提交记录**（署名/版本/可回退）；纯文档/草稿严格走"私有区定稿→提交"。② 审批默认：**文档类提交需审批、代码类提交无需审批（留痕即可）、高危命令需审批**；均可配置为更强策略。"阶段基线锁定"按 P1 预留，MVP 不做。 |
| D14 | 文档评审轮补充确认（2026-09-08） | ① **默认团队**：创建项目默认勾选全部 8 个内置模板（向导可取消）。② **产出布局**：按类型子目录默认布局（doc→`workdir/docs/`、code→按仓库结构、test→`workdir/tests|test/`、deploy→`workdir/deploy/`；已有仓库以现结构为准），可配置。③ **同角色多实例**：MVP 不支持（每项目每模板至多 1 实例），多实例（dev_1/dev_2…）放入后续版本迭代。④ **日志暴露**：UI 提供原始事件时间线查看（默认对话视图，可切换时间线并过滤 kind），检索/摘要/导出保留。⑤ **会议邀请**：成员是否入会由**成员 Agent 自主决定**（暂停当前任务到可中断点→入会；散会后回到原工作，并依据会议结论自主评估当前工作是否受影响、如何调整；决定全程留痕、用户可见可干预）。⑥ **MVP 会议并发**：同一项目同一时刻至多 1 个进行中会议，其余发起/邀请排队等待（可配置放开）。⑦ **流式语义**：流式回复以最终落盘消息为准，半截内容为临时态不入 log；崩溃/刷新后 UI 标记"（未完成）"并可补全/重说。⑧ **代码产物聚合**：受控编辑以**任务为单位**自动聚合成 artifact（无任务上下文时按回合兜底）。⑨ **实例移除**：删除实例=停用并保留全部数据（会话归档可查、工作区/记忆保留、可重新启用）；彻底删除数据需另行确认（后续版本）。⑩ **会议内读取**：会议内 fs 读 workdir+ro://，本人私有区经 ws_read 可读（一切写入与他人私有区读取禁止）。 |
| D15 | PM 定位与任务通道（2026-09-08 文档评审轮；对 D1/US-3/FR-08 的 MVP 口径更新） | **乙方案为 MVP 默认**：任务由用户经 UI 创建/指派/流转；PM 不直接创建任务，职责收敛为协调进度、组织/主持会议、需求对齐、进度播报（协调信息落会话与全局记忆，不做结构化任务记录）。**甲方案能力一并实现但默认关闭**：`task_*` 工具组（task_view/task_list 只读，task_assign/task_update 写）注册并随服务提供，默认不出现在任何角色工具矩阵（config `task.assignByAgent: false`）；将来开启即切到"PM 拆解直接指派"模式（受派者正在执行用户指派任务时需用户确认），用于 A/B 对比效果。 |
| D16 | 文档评审轮 2 补充定案（2026-09-08；对 A1~A6 的归档） | ① **会议状态与排队持久化**：会议会话发起即创建并全量落盘；状态 `queued(排队,不占槽)→proposed(邀请征询,占槽)→open⇄blocked_waiting_user→closed`；征询期（proposed）主持人可回 user 会话工作，≥1 成员接受才 open 并正式拉入主持人；queued 在槽空后自动转 proposed，重启可恢复。② **suspended 收敛**：会话级 suspended 保留并落盘（user 会话在 Agent 被会议占用/重启恢复期置 suspended）；Agent 级状态 MVP 收敛为 `idle/working/meeting/waiting` 四态（移除 suspended），P1「暂停 Agent」(hangup) 再引入。③ **plan-execute 回合语义**：单回合内多步长跑（turn_end 在计划完成汇报时写入）；回合内暂停仅两类——审批（Agent waiting）与会议抢占（到可中断点）；恢复由 dispatcher 在同一会话内续跑（plan 事件为依据）；用户普通消息回合内只入队不打断；跨重启**不自动续跑**（缺 turn_end=未完成，用户下一条消息触发 Agent 汇报中断点/选择续做）。④ **任务激活规则**：每 Agent 至多 1 个 `in_progress`（新置 in_progress 时原任务自动回 todo 并 UI 提示）；仅 in_progress 任务注入上下文并作代码聚合锚点，todo/会话口头指派不入上下文（改动按回合兜底）；会议纪要转任务 creator=user（用户 UI 点击转出，来源挂会议），Agent 直建任务仅甲模式。⑤ **角色模板快照绑定**：实例创建时快照模板默认值（prompt/tools/审批规则），此后模板增删改不影响既有实例；删除被引用模板仅 UI 标「模板已移除」；取消「同名文件覆盖内置」说法，改为 UI「基于内置复制新建」单一路径。⑥ **doc 审批预览**：doc 类提交命中审批时，提交服务生成**只读预览**（文本=内容预览；二进制/设计稿=文件信息+大小）随审批卡片提供并落审批记录引用；不开放私有区整体浏览。 |

## 8. 边界与不做事项（MVP）

- 不做账号/权限体系、不做远程/云端部署、不做多用户实时协同编辑。
- 不做 Agent 间 1:1 私聊（沟通统一进会议；会外协作以产出物+全局记忆为媒介）。
- 不做代码自动执行到生产环境的持续部署（运维产出部署脚本与手册，由用户执行）。
- 不做 SQLite/外部数据库；不做消息加密。
- 不做多语言 UI（中文优先，后续可扩展 i18n）。
- 不在工作目录自动 git 操作（除非用户授权的高危审批）；不隐式安装第三方运行时（如 Docker）。

## 9. MVP 成功标准与验收方式

1. **可跑通全流程（验收主路径）**：本机 `npm run dev` 起服务 → 创建项目(选空目录；角色默认全勾 8 个内置模板，向导中可取消至 3~4 做精简演示) → 与产品经理对话产出 PRD 草稿 → 提交产出物进工作目录 → PM 发起会议(开发+测试) → 会议中某点阻塞等用户拍板 → 用户答复后会议继续并出总结 → 全局/角色记忆可见 → 关闭浏览器重开仍能恢复会话。验收人：用户本人按上述脚本走通。
2. **Mock 模型全流程可用**：无任何 API Key 也可演示完整闭环。
3. **单工与状态正确**：同一 Agent 不会同时出现在两个活动会话中处理；状态面板与实际一致。
4. **安全**：高危命令无审批不可执行；Agent 无法读写工作目录与私有区之外的文件。
5. **文档交付**：全套文档评审通过；编码阶段按 docs/plan/development.md 执行。
