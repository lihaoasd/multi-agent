## 1. 背景与目标

用户（个人开发者/小团队老板）希望在**本机**用一个由多个 AI 角色组成的虚拟研发团队完成软件开发。
平台是**场景引擎**的软件研发首场景：角色可抽象、可扩展，未来支持用户自行编辑角色与团队，套用到任意场景。

目标：用户以"老板"身份创建软件项目 → 组队（角色实例）→ 通过 1:1 会话驱动团队 → 产出物（文档/代码）落在选定工作目录 → 用户审批关键节点 → 得到可运行、可部署的软件。

## 2. 目标用户与使用形态

- 目标用户：懂软件开发的个人/小团队（本项目首个使用者即用户本人）。
- 形态：本地部署 Web 应用（Node.js 服务 + 浏览器访问 http://127.0.0.1:PORT），单机运行，不做多租户与账号体系（本机即用户）。

## 3. 核心角色设定

| 参与者 | 说明 |
| --- | --- |
| 用户(老板) | 决策者：提需求、决策、审批、指派；不是 Agent。 |
| PM Agent | 独立角色：协调进度、对齐需求与目标、把模糊目标推进为可执行安排；**可按编排图向下游委派任务**（见 D15/D19）。 |
| 产品经理 Agent | 需求澄清、编写 PRD、维护需求范围。 |
| 系统架构师 Agent | 技术方案、模块/接口/数据设计，评估可行性。 |
| 交互设计师 Agent | 流程、信息架构、交互说明。 |
| UI 设计师 Agent | 视觉方案、设计稿/规范。 |
| 高级开发 Agent | 编码实现、自测、重构。 |
| 测试工程师 Agent | 测试计划/用例、执行与缺陷报告。 |
| 运维工程师 Agent | 构建部署、环境脚本、监控与发布说明。 |

- 以上为**内置模板**；所有角色可**抽象增删**：系统级角色库维护模板；项目级实例化组队。
- 暂不确定是否每项目必须全角色——由用户创建项目时自主选择，不做强制。

## 4. 用户故事（US）

- **US-1 创建项目**：作为老板，我创建项目时输入名称、描述并**选择工作目录**（支持空目录/已有代码仓库），系统生成团队与初始会话，让我立刻能对话。
- **US-2 一对一指挥**：我打开某 Agent 的会话窗口直接聊天：提问、下达任务、追问、修正；Agent 答复（可含思考过程与工具动作）。
- **US-3 委派与执行**：我把任务委派给某 Agent（经 UI 创建/指派，D15：MVP 默认由用户驱动）；Agent 在**项目工作目录**内工作（读代码/写文件/跑命令/自测，目录内容对所有角色可读），关键结果汇报到会话，产出按提交制登记进入工作目录。
- **US-4 进度可视**：我能看到每个 Agent 的状态（空闲/工作中/等待中）与当前所在会话。
- **US-7 切换与恢复**：任意时刻我关闭浏览器/重启机器，重开后能继续任意会话，Agent 依据 session log 与记忆恢复上下文。
- **US-8 历史检索**：我能在项目内按关键词检索历史会话与记忆。
- **US-9 已有代码库**：我指向一个已有仓库作为工作目录，团队先读代码/结构再谈需求与改动。
- **US-10 自定义角色**：我在系统角色库新建角色模板：名称、职责、系统提示词、agent loop、模型；随后可在任意项目使用。
- **US-11 自定义团队**：创建项目时我从角色库勾选成员（默认全勾 8 个内置模板，D14-1）、可改名/调提示词/换模型/换 loop；项目进行中也可增删成员（MVP 删除=停用保留数据，可重新启用，见 D14-9）。
- **US-12 产出物管理**：Agent 提交的产出物（文档/代码/测试/部署包）在工作目录可见；我能在界面查看提交记录（署名/版本/摘要）并回退。
- **US-13 审批**：高危命令与（按策略）关键提交需我批准后才执行/入目录。
- **US-14 多项目**：我能在项目列表页新建/打开/删除多个项目（当前 MVP 顺序处理互不干扰）。
- **US-15 工具包浏览**：我在首页工具模块看到工具包列表，能展开看每个包里有哪些工具、用途与风险；MVP 不能自制工具包（后续开放）。
- **US-16 Agent 库浏览**：我在首页 Agent 模块看到 Agent 模板列表，逐个可见 **loop / 提示词 / 工具 / 模型**（以及场景标签与审批规则）；其中模型/loop/提示词可编辑提交（US-23），工具挂载仍只读。
- **US-17 编排画布**：在项目页拓扑导航里，我看到每个 Agent 的卡片与它们之间的有向连线；我能增删 Agent、连线、编辑布局并保存，从图上观测整体工作情况。
- **US-18 会话与工作日志**：在项目页对话导航里，我用左栏切换各个角色的会话，中栏看消息与 Agent 的**思考 / 工具调用**（直接内联，无需展开），右栏看任务/询问/审批（**S22 起不再有事件筛选与"工作日志"折叠**）。
- **US-19 对话即启动与自动委派**：我在某个 Agent 的会话里对话，就等于让该 Agent 开始工作；它会按编排图沿出边创建并委派任务，受派 Agent 领取后独立执行。
- **US-20 询问答复**：Agent 需要我决策时向我提问，我在右栏询问列表里答复，它继续干活。
- **US-21 暂停与停止**：我可以暂停某个 Agent（不再领新任务）或停止它当前的任务。
- **US-22 模型供应商配置**：我在首页模型模块添加/编辑/删除模型供应商（预置 DeepSeek / OpenAI / Anthropic / Gemini / 通义百炼 / Kimi / 智谱 GLM / 火山方舟 / Ollama，或自定义），填写地址与密钥、测试连通性、拉取或手工登记模型条目，并在 Agent 模块把这些条目分配给角色（**S14 起不再有"全局默认模型/loop 步骤默认模型"**）。
- **US-23 Agent 配置提交**：我在首页 Agent 模块基于内置复制新建或编辑模板，配置**提示词 / agent loop / 模型**；在项目内还能为单个 Agent 覆盖这三项，并看清该实例当前生效的配置。

> 编号空缺（US-5/US-6）表示该需求已随"会议功能移除"（2026-09-14）删除；编号不复用。

## 5. 功能需求（FR，MoSCoW）

### P0（MVP 必须）

- FR-01 项目管理：列表、创建（名称/描述/选择工作目录/勾选角色）、打开、删除（仅删运行时数据，提示不影响工作目录）。
- FR-02 角色抽象与实例化：角色模板库（内置 8 个软件团队模板 + 用户自建，带**场景标签**）；**首页 Agent 模块只读展示**模板的 loop/提示词/工具/模型（配置提交后续，见 FR-27）；项目内实例可改名/改提示词/换模型/换 loop；Agent 状态可见。
- FR-03 用户↔Agent 1:1 会话：消息收发（流式）、会话历史加载、并发约束(单工)下的排队与提示。
- FR-04 Agent 单轮执行：按所选 agent loop 执行一次回复；思考/工具调用/结果以事件流推给前端并**全量落日志**。
- FR-05 消息与会话日志：每会话结构化全量日志(JSONL)；会话列表/历史/恢复加载。
- FR-06 共享工作目录与文件归属（2026-09-14 修订：取消私有工作区）：所有角色的产出都在**项目工作目录**内进行；目录内容**全员可读**（角色间共享）；每个文件按 `file-owners` 归属创建者，**只有归属者可修改**，他人只能另建新文件（用户本人不受归属校验）。
- FR-07 产出物提交制：Agent 将产出整理为 Artifact 提交(署名/类型/文件清单/摘要/版本)；落地工作目录并写 manifest；可回退。
- FR-08 任务轻量管理：任务含标题/受派者/创建者/状态/关联会话/产出物，右栏任务列表可见；**Agent 委派为默认**（D19-④/⑤）：Agent 只能沿编排图**出边**创建/委派任务，受派者**领取**后执行；用户仍可手动派单、改状态、终止与干预，**不受边约束**。**S36/D39 补**：受派人 `done`/`blocked`/`terminated` 汇报后，委派人被唤醒的通知是"事实 + 据此继续"（不只是播报）；委派人上下文注入 `[委派任务]`（自己派出去的任务及状态），"接收到回报"因此跨回合成立。
- FR-10 模型接入与路由：四种协议适配器（`openai-compatible` / `anthropic` / `gemini` / `ollama`）；**用户可添加常见供应商与模型条目**（FR-34）；按角色/loop 步骤可配置不同模型。出厂**不含任何供应商与模型**，也不含任何"假模型"（S10 已删除 mock 适配器）。
- FR-11 记忆（双层+全文）：会话全量日志、滚动摘要、角色长期记忆、项目全局记忆；关键词检索（先全文+简单索引，向量留扩展点）。
- FR-12 UI：全局导航（项目 / Agent / 工具）；项目页双导航——**拓扑页 2 栏**（左编排画布 + 右任务/询问/审批）与**对话页 3 栏**（左会话切换 + 中会话流含对话/思考/工具调用 + 右三列表）；询问卡与审批卡；流式打字效果（详见 FR-25/28/29/30 与 [design/ui.md](../design/ui.md)）。
- FR-13 工具执行与安全：文件读写限定在**项目工作目录**内（+只读平台资源）；他人产出物只读；命令执行限制在项目工作目录内；高危动作（删除/覆盖大范围/安装依赖/改配置/git 变基等）走用户审批；全程记录审计轨迹。
- FR-14 单工调度：Agent 同一时刻只有一个活动会话；其余消息排队，到可中断点后处理。
- FR-25 首页与全局导航：**项目 / Agent / 模型 / 工具**四模块（2026-09-15 由 D20 修订，原为三模块）；进入默认落在项目模块；四模块均可浏览，其中模型配置与 Agent 三项配置可提交（FR-34/FR-35），工具包仍只读（FR-26）。
- FR-26 工具包展示：工具按**包**组织展示（MVP 8 个基础包：`fs`/`cmd`/`memory`/`session`/`artifact`/`approval`/`task`/`interaction`，**全员必选**；`interaction` 承载 `ask_user`，S13/D23）；可见包内工具、用途与风险；**自定义工具包制作后续**（U8）。**S25 起「全员必选」是强制的**：模板与实例的 `packages` 在**读/写两侧统一归一**，缺基础包的旧数据在读取时自动补齐（不改磁盘），见 D30。
- FR-27 Agent 模块：模板列表与详情，含 **loop / 系统提示词 / 工具（按包分组）/ 模型 / 审批规则 / 场景标签**；其中 **模型、loop、提示词三项可提交配置**（FR-35），工具与工具包挂载仍只读（U9 剩余）。
- FR-28 项目编排画布：节点 = Agent 实例卡片，有向边 = "可创建/委派任务"的关系；**S17 起分「浏览 / 编辑」双模式**（默认浏览：点节点卡片打开该 Agent 的会话、只读观测；编辑模式：增删节点、连线、拖拽移动、删除边与**保存**）；保存校验：无自环、无重复边、节点属本项目、`version` 乐观并发；节点显示**状态徽标与当前任务**，用于观测总体工作情况。
- FR-29 项目页布局：**拓扑页 2 栏**（左画布 + 右三列表）、**对话页 3 栏**（左会话切换 + 中会话流 + 右三列表）；右栏三列表（任务/询问/审批）两页共用。
- FR-30 会话流内容：会话流内联展示**对话（`message`）+ 思考（`thought`）+ 工具调用（`tool_call`，含紧随的 `tool_result`）+ 错误（`error`）**，全部**直接展示、不做折叠包装**；**不提供事件筛选**（S22/D28 修订：原"默认折叠、可展开 + 仅对话/全部事件切换 + 按 kind 过滤"取消）。**对话消息按 Markdown 渲染**（**S27/D32 起用 `react-markdown` + `remark-gfm` 框架渲染**：标题/段落/围栏代码块/列表/引用/分隔线/**GFM 表格**/删除线/任务列表/自动链接 + 行内粗斜删/代码/链接；**不注入 HTML**、URL 走框架默认白名单；D29 的自研解析器已删除）。**工具结果条目成功时只显示工具调用名称**（S26/D31；**S34/D37 补：失败时必须显示报错正文**，如 `[ERR_FORBIDDEN] …`，整行标红）；**工具调用参数默认折叠**（S28/D33：默认只显示 `工具调用 <工具名> · #seq · turn N`，点击展开看格式化参数；无参数时无空面板）。会话窗口还提供**「详细日志（trace）」视图**（S35/D38）：一次列出**原始事件全量**（含 `plan`/`turn` 边界/`state`/`summary` 等），每行 `#seq · 时间 · turn · kind` + 摘要，可按需展开原始 payload。原始事件流水仍可按 kind 拉取（接口能力不变，规则 13）。
- FR-31 对话即启动与自动委派：用户在 Agent 会话中发消息即让该 Agent 开工；**各 Agent 独立工作**，不设项目级运行状态；Agent 按**出边**委派任务，受派者领取执行，完成/受阻**沿同一条边反向汇报**；越权委派被拒（`ERR_ORCHESTRATION_EDGE`）。**平台在每次模型调用里都要给到工具通道**（S30/D34）：拿到工具结果后的追问同样带上 `tools`，否则模型只能把工具调用写成文本协议（DeepSeek 的 DSML）→ 调用从未执行且脏标记落进会话；模型若仍以文本形式发起调用，平台**按 DSML 解析成真实调用**（走同一套策略/审批/归属闸门），无法解析的片段从正文剥离并记诊断。**S36/D39 补**：反向汇报不止唤醒委派人，还给出"据此继续"的下一步指引，并在委派人上下文中列出它派出去的任务及状态。
- FR-32 询问与答复：Agent 可向用户提问（问题 + 选项）并**阻塞等待**（Agent 状态 `waiting`）；**答复入口在会话窗口（发送输入框上方）**——有选项点选、无选项填文本，答复后 Agent 继续；右栏「询问」列表与「任务与产出物」标签**只做提示**（显示谁在问什么 + 「到会话里答复」跳转）；每 Agent 同一时刻至多 1 个待答询问（S32/D35 修订；**S33/D36 再修订：询问卡一次只显示一题，可左右滑动/按钮切题，答完必答题后一次提交**）。
- FR-33 暂停与停止：Agent 级控制——**暂停**=不再领新任务、当前回合到可中断点挂起；**停止**=终止当前任务（存在未结算改动时先结算为 code artifact 快照）；均需确认并留审计。**S37/D40 修复**：暂停**当场**中断在途回合（中断信号不排队等 `drain` 的锁——`drain` 持锁跑完整个队列，等锁释放再中断等于没停）；被中断的回合在可中断点收尾且**游标不推进**（消息留在队列，`resume` 后补处理）；中断后**不再自动续跑**队列；中断事实落一条 `state{turnAborted}`。**停止生成**（`stop{scope:'turn'}`）＝本条消息作废、不重放，剩余队列留待下次触发；界面在"没有在途回合"时如实提示而不假报成功。
- FR-34 模型配置模块：供应商 CRUD（9 家预置 + 自定义：kind/名称/地址/凭证）、**凭证双模式**（明文文件或环境变量引用）且读路径永不回传明文、连通性测试与模型发现、模型条目管理（**S14 起不再有"全局默认模型/loop 步骤默认"——模型由 Agent 模板默认或项目实例覆盖指定**）；配置写入 `data/model-config.json` 并**即时生效（无需重启）**；删除被引用的供应商或模型返回 `ERR_CONFLICT` 并点名引用者（详见 [design/model-config.md](../design/model-config.md)）。
- FR-35 Agent 配置提交：系统模板（基于内置复制新建 / 编辑 / **停用** / **删除用户模板**）与项目实例覆盖的 **提示词 / agent loop / 模型** 三项写入；支持**勾选后批量设置默认模型**（含"未配置模型"的一键配置，见 D22）；含校验（loop 策略须已注册、参数取值合法、模型须为已启用模型条目、提示词长度上限）；含生效范围（模板只影响**未来新建实例**，实例覆盖在**下一回合**生效，运行中回合到可中断点）与留痕（平台配置审计 + 模板历史快照）。内置模板的提示词/loop 仍只读（可复制新建），但**默认模型可改**、**可停用**；删除仅对用户模板开放且被项目引用时拒绝（D22）。工具与工具包挂载不在本轮（U9 剩余）。

## 6. 非功能需求

| 项 | 要求 |
| --- | --- |
| 运行环境 | 本机 Windows(Win10/11)/macOS/Linux；Node.js ≥ 20；浏览器 Chrome/Edge。 |
| 存储 | **纯文件系统**（JSON/JSONL/Markdown），不用 SQLite/外部 DB；拷贝运行时项目文件夹即可迁移。 |
| 实时性 | 消息、Agent 状态、任务/询问/审批、编排图变更均走 WS 推送；回复流式输出（WS chunk），首字延迟目标 < 2s。 |
| 安全边界 | 所有 Agent 文件/命令活动被限制在：该项目工作目录(+只读平台内置模板)；写入另受**文件归属**约束（只能改自己名下或无归属的文件，他人产出物只读）；高危需审批；日志审计。 |
| 凭证安全 | 模型供应商密钥只以两种形态存在：`data/model-config.json` 明文（`data/` 不入库）或环境变量引用；**任何接口响应、日志、审计、错误事件都不含明文**（只回掩码与"是否已填"）。 |
| 可恢复性 | 服务/浏览器随时可重启；会话状态落盘可重建；不丢已落日志。 |
| 可扩展性 | 角色模板/loop/模型 Provider/工具集/产出物类型/前端面板均有稳定扩展点。 |
| 易用性 | 全程中文 UI；出厂不含任何供应商与模型（也不含假模型），未配置模型的 Agent 启动回合时必须在界面上给出**明确引导**（`ERR_MODEL` + 配置入口指引），不做隐式降级；本机具备 Ollama 时可用本地模型离线跑通。 |

## 8. 边界与不做事项（MVP）

- 不做账号/权限体系、不做远程/云端部署、不做多用户实时协同编辑。
- 不做 Agent 间 1:1 私聊，也不做多方会话（跨角色协作以任务委派 + 产出物 + 全局记忆为媒介）。
- 不做代码自动执行到生产环境的持续部署（运维产出部署脚本与手册，由用户执行）。
- 不做 SQLite/外部数据库；不做消息加密。
- 不做多语言 UI（中文优先，后续可扩展 i18n）。
- 不做密钥加密/系统钥匙串集成（本机单用户；密钥只以"明文存 `data/`（不入库）或引用环境变量"两模式存在，见 model-config.md §5）。
- 不做模型配置的版本回滚交互、模型用量/费用统计、网络代理设置（分别为 U15/U13/U16）。
- 不在工作目录自动 git 操作（除非用户授权的高危审批）；不隐式安装第三方运行时（如 Docker）。

## 9. MVP 成功标准与验收方式

1. **可跑通全流程（验收主路径）**：本机 `npm run dev` 起服务 → 首页看到工具包（8 个基础包）与 Agent 模板（含场景标签）→ 创建项目（选空目录；角色默认全勾 8 个内置模板）→ 进入项目页拓扑导航，画布连线（如 `pm → dev`、`dev → qa`）并保存 → 切到对话导航，在 PM 会话发消息（＝启动）→ PM 沿出边委派任务 → dev 领取开工 → dev 需要我决策时提问、我在右栏询问列表答复 → dev 汇报完成 → 我在右栏任务列表确认 → 产出物与记忆可见 → 关闭浏览器重开仍能恢复会话与画布。验收人：用户本人按上述脚本走通。
2. **未配置模型的明确引导（S10 修订；S14 再修订）**：出厂不含任何供应商与模型（也不再有任何假模型）；新建项目的 Agent 生效模型为空；此时启动回合返回 `ERR_MODEL`（「该角色还没有可用模型：请在「模型」模块添加供应商与模型条目，并在 Agent 模块或项目内为它选择模型」）——**不静默降级、不自动造模型**。用户在 Agent 模块为模板配置默认模型（影响此后新建实例）或在项目内为实例配置模型（S14 起生效链只有两级，**没有平台级默认**）后，全流程即可跑通。
3. **单工与状态正确**：同一 Agent 不会同时出现在两个活动会话中处理；状态面板与实际一致。
4. **安全**：高危命令无审批不可执行；Agent 无法读写项目工作目录之外的文件；他人产出物不可修改（`ERR_FORBIDDEN`）。
5. **文档交付**：全套文档评审通过；编码阶段按 docs/plan/development.md 执行。
6. **编排约束生效**：Agent 向非出边节点委派任务被拒绝（`ERR_ORCHESTRATION_EDGE`），画布不产生新边；用户手动派单不受此限制。
7. **控制与询问可用**：暂停后该 Agent 不再领取新任务且当前回合到可中断点挂起；停止后当前任务终止（未结算改动已先结算为 snapshot）；询问与审批均可在右栏原地处理，处理完 Agent 继续。
8. **模型配置与 Agent 配置可用**：首页模型模块能添加任一预置供应商（预置目录 **9 家**，不含任何假模型；离线可用本机 Ollama 验证）、填密钥、**测试连接**、登记模型条目（S14 起**无"默认路由/全局默认模型"**）；Agent 模块能"基于内置复制新建"模板并修改**提示词 / loop / 模型**（内置模板默认**不配置模型**），项目内实例可覆盖这三项；**模板库支持停用（含内置）与删除（仅用户模板，被项目引用时拒绝并点名）**；**支持勾选模板一键配置默认模型**；模型模块按"未配置模型的 Agent 计数"提示未配置项，消除路径为"Agent 模块批量配模板默认（影响新建实例）或在项目内为既有实例配置模型"；改完**无需重启**即在下一回合/下一次调用生效；删除被引用的供应商或模型被拒并点名引用者；密钥在页面、接口响应与审计中只以掩码出现。
